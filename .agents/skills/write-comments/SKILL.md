# 주석 작성

주석 추가·정리 요청에 적용한다. [코딩 컨벤션](../../../docs/coding-convention.md)의 주석 규칙을 먼저 읽고 단일 기준으로 사용한다. [소유권 확인](../check-code-ownership/SKILL.md)은 실제로 다른 담당자 영역을 수정하는 경우에만 적용한다.

## 작성 기준

- 코드만 읽어서 알 수 있는 동작을 반복하지 않는다. 숨은 계약·제약·판단 이유·후속 작업을 설명한다.
- "무엇"은 한 줄로 쓴다. 길어진 설명은 이름이나 구조로 해결할 수 있는지 확인하되, 주석만 요청받았다면 리팩터링으로 범위를 넓히지 않는다.
- 되돌리면 깨지는 이유, 버린 대안, 실측으로 바뀐 전제와 경계값의 근거는 필요한 만큼 설명한다.
- 코드 주석에는 문서 절 번호·파일 경로 대신 이유 자체를 남긴다. 한 줄 주석은 짧은 구절로, 여러 줄 설명은 문장으로 쓴다.
- 한국어 설명은 유지하고 기호는 코딩 컨벤션의 ASCII 규칙을 따른다. `->`, `-`, `!=`, `<=` 등을 사용한다.
- C# public API의 외부 계약은 `/// <summary>`로 적는다. 내부 판단은 `//`로 적고, 다른 XML 태그를 추가하지 않는다.
- 후속 작업은 실제 담당자를 아는 경우 `// TODO(담당자): 내용`으로 남긴다. 담당자를 임의로 만들지 않는다.

## 수정 범위와 검증

1. 대상 코드에서 공개 계약·서버 권위·수명·재시도·중복 방지 등 설명이 필요한 부분을 읽는다. 모든 줄을 주석으로 채우지 않는다.
2. 팀 소유 소스만 수정한다. Mirror·외부 에셋·생성 코드와 저작권·라이선스 고지, 생성기·린터·컴파일러 지시문은 보존한다.
3. 주석만 바꾸는 요청에서는 실행 토큰, 전처리 지시문, 직렬화 필드와 문자열을 변경하지 않는다. 로그·화면 문자열 정리가 필요하면 별도 범위로 제안한다. 다른 언어에는 해당 언어의 주석 문법을 사용한다.
4. 최종 diff를 확인해 반복 설명, 문서 위치 표기, 금지 기호·XML 태그와 주석 밖 변경을 검토한다. 주석 변경으로 기능 검증까지 했다고 보고하지 않는다.
