# 게임 VFX 제작

사용자가 승인한 컨셉과 패턴 계약을 Unity에서 재생 가능한 효과로 만든다. 기존 작업을 이어갈 때 승인된 단계와 원본을 재사용한다. 이미 받은 승인을 다시 묻지 않는다.

## 시작과 범위

- 저장소 루트 AGENTS.md와 docs/unity/ART_ASSET_PRODUCTION_WORKFLOW.md, SCENE_AND_ASSET_SAFETY.md, docs/ai/03_VERIFICATION_PLAYBOOK.md를 읽는다. C# 수정은 docs/coding-convention.md를 따른다.
- 패턴별 효과 목록, 실제 판정 형태·치수·원점·방향·안전구역·타격 수·예고/타격 시점을 코드와 기획에서 확인한다. 표시 번호를 서버 enum 번호로 간주하지 않는다. 불명확한 게임 디자인만 사용자에게 질문한다.
- 기존 프리팹·재질·셰이더·원본과 다른 작업자의 변경을 확인한다. 재사용 가능한 효과는 개선하고 중복 재생기를 만들지 않는다.
- 사용자 지정 모델·reasoning·작업 분담을 따른다. 위임이나 교차 검토가 필요하면 프로젝트 AI 모델 선택 지침을 읽는다. 특정 모델명이나 이전 API 전송 승인을 새 작업의 보편 기본값으로 삼지 않는다.

## 레퍼런스와 컨셉 검토

1. 첨부 이미지를 실제로 열어 보고 영상은 지정 구간의 여러 프레임과 움직임을 확인한다. 정지 이미지의 선 모양뿐 아니라 등장 순서·확산 속도·밀도·잔상·소멸을 설명한다.
2. 색감, 실루엣, 발광 중심/주변 대비, 지면 흔적, 균열, 충격파, 파편·먼지의 역할을 분리한다. 품질 참고 요청을 색상 교체 요청으로 해석하지 않는다.
3. 컨셉이 없거나 컨셉 제작을 요청받았다면 imagegen 스킬과 이미지 생성 도구로 효과별 시안을 만든다. 패턴별로 구분해 보여 주고 컨셉 검토를 요청한 경우 승인 후 제작한다. 이미 승인된 시안은 다시 생성하지 않는다.
4. 원화와의 차이를 구체적인 항목으로 기록한다. '80% 이상' 같은 목표를 근거 없는 달성 수치로 보고하지 않는다.

## Blender 제작과 GPU

- Blender MCP로 현재 파일·씬·렌더 설정을 먼저 확인한다. 연결이 안 되면 사실을 알리고, 사용 가능한 설치 Blender의 백그라운드 실행 등 허용된 대안을 사용한다. 연결된 척하거나 다른 작업의 씬을 덮어쓰지 않는다.
- 기본 GPU 설정은 지원 장치를 조회해 Cycles GPU Compute를 씬에도 적용한다. 사용자 요청에 따라 지원 GPU·CPU를 활성화하되 실패 장치·드라이버 한계를 기록한다. Eevee가 명시되거나 승인된 효과 작업은 Eevee를 사용하고 Cycles 혼합 렌더와 구분한다. 설정값과 실제 GPU 사용 증거를 구분하며 CPU·GPU 100% 사용을 보장하지 않는다.
- 여러 작업자가 같은 Blender/GPU를 사용하면 렌더 작업을 조정해 충돌과 메모리 부족을 피한다.
- 실제 미터·피벗·로컬 진행 방향을 맞춘다. 예고, 지면, 균열, 충격파, 플래시, 이동 머리, 파편을 필요한 만큼 독립 레이어로 구성한다. 모든 효과에 동일한 레이어를 강제하지 않는다.
- Emission과 Noise/Voronoi/Gradient 등 절차적 질감으로 불규칙성을 만들고 Alpha로 자연스럽게 소멸시킨다. 과노출로 세부가 사라지거나 평면 카드의 사각 경계가 보이지 않게 확인한다. Bloom/Glare/Color Management는 설치 버전에서 실제 지원되는 방식으로 설정한다.
- 한 번에 표시하는 예고는 테두리 그리기 애니메이션으로 바꾸지 않는다. 지면 장판이 요구되면 검은 지면·연결된 균열·불규칙한 가장자리 등 승인된 구성을 유지한다. 무철의 금색·검은 장판을 다른 VFX의 공통 색상으로 고정하지 않는다.
- 바위 등 불투명 부품은 재질·노멀·거칠기·실제 AO를 검토한다. Unlit 발광 레이어는 AO 생략 이유를 기록한다. LOD·Collider는 용도와 화면 크기에 맞추고 표현 프리팹에 피해 판정을 추가하지 않는다.
- .blend, 재현 가능한 제작 스크립트, 출력 텍스처/메시와 시간 데이터를 보존한다. 원본은 Assets 밖 사용자 지정 저장 폴더에, 개인 상세 기록은 프로젝트 지정 기록 폴더에 둔다.

## Unity 적용과 시간 제어

- unity-mcp-orchestrator 스킬로 연결·상태를 확인한다. Unity 호환 메시/텍스처/재질을 임포트하고 Assets/02.Prefab/ 아래 재사용 프리팹, 안전한 전용 개발 씬을 만든다. 기존 통합 씬과 외부 유료 에셋 원본은 보존한다.
- 축·스케일·피벗·UV·알파·색 공간·압축·셰이더·재질 참조를 실제 임포트 결과로 확인한다. Blender 노드가 Unity에 자동 변환된다고 가정하지 않는다.
- 기존 시간 제어 구조를 우선 사용한다. 패턴별 SO/Inspector로 예고·확산·유지·소멸·파편과 필요 시 돌진 시간을 조절한다. 서로 다른 설정을 의도치 않게 공유하지 않게 하고 공유 SO의 영향 범위를 안내한다.
- 로컬 미리보기와 서버 확정 재생을 구분한다. 전투용은 외부 예고 시작·예정 타격·확정 타격·현재 시각을 같은 시계로 받는다. 실제 보스 연결이 요청 범위가 아니면 공개 사용 계약과 연결 대기 상태를 남긴다.
- 재생 취소·비활성화·풀 반환 정리, 늦은 확정과 중첩 재생을 고려한다. 인스펙터 선택 해제가 외부 재생을 끊거나 재생성 도구가 사용자 시간 설정을 덮어쓰지 않는지 확인한다.
- JSON 등 중간 데이터를 사용하면 누락 nested 객체가 0으로 초기화되는 경우를 구분하고 필수 값·배열 길이·유한수·시간 계약을 검증한다.

## 검증·캡처·사용자 검토

- 컴파일과 신규 콘솔 오류, .meta/GUID, 누락 재질을 확인한다. 정상 재생과 취소·확정 누락·시간 변경 등 해당 변경에 의미 있는 동작을 실행한다.
- 실제 게임 카메라에서 예고/타격/잔상/소멸을 확인한다. 중심점뿐 아니라 파편·입자 크기를 포함한 경계와 안전구역 침범을 표본 검사한다. 직선 폭·길이와 돌진 끝 방향을 확인한다.
- 실제 Unity 캡처를 번호별로 저장하고 직접 열어 프레이밍·과노출·장판 가독성을 확인한 뒤 사용자에게 보여 준다. Blender 렌더나 생성 이미지를 Unity 실행 결과로 표시하지 않는다. 움직임이 핵심이면 짧은 영상이나 단계별 캡처도 제공한다.
- 사용자가 1차 완성 후 확인을 요청했다면 그 지점에서 멈추고 응답 후 추가 보정한다. 검증 실패 수정은 검토본 준비 범위 안에서 처리한다.
- 정적·기능·통합·성능 검증을 구분한다. 실행하지 않은 빌드·M2/M3·성능과 주관적 품질 평가는 미검증으로 남긴다.

## 사용 안내와 마무리

- 담당자가 사용할 프리팹, 배치 원점·방향·스케일, Inspector 설정, 재생/확정/Tick/Stop API, 공유 설정·취소·지연·중첩 제약과 실제 검증 범위를 docs/의 자립적인 사용 안내에 적는다. 다른 담당자 전달 기록은 write-handoff 절차를 따른다. 문서 작성만으로 상대에게 메시지를 보내지 않는다.
- 완성 효과는 register-vfx-prewarming 스킬을 따라 해당 전장/스킬의 준비 대상에 등록한다. 문서 목록과 실제 로더 소비를 구분하고 프리워밍 구현을 임의로 확대하지 않는다.
- 커밋 요청이 있으면 guided-commit으로 관련 파일과 .meta만 묶는다. 원본·개인 렌더·다른 파트 변경을 포함하지 않는다. 프로젝트 결과는 AGENTS.md의 osk 기록 절차를 따른다.
