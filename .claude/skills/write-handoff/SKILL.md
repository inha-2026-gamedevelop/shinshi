# 인수인계 작성

## 언제 발동하나

- 사용자가 인수인계를 요청한다. 예: "인수인계 남겨줘", "핸드오버 문서 써줘", "여기까지 정리해줘", "다음 세션이 이어받게 해줘".
- 사용자가 작업을 중단하거나 종료하겠다고 밝혔는데 남은 일이 있다. 예: "오늘은 여기까지", "이건 나중에 하자".
- 다인 접속 테스트(M2 이상), 다른 파트 인터페이스 확정, 게임 디자인 결정 등을 기다리며 작업이 멈췄다.
- 여러 단계 중 일부만 완료했거나, 커밋하지 않은 작업물이 남아 있다.

작업이 완전히 끝났고 커밋까지 마쳤으며 남은 위험도 없으면 인수인계를 새로 만들지 않는다. 현재 작업 색인이 있으면 그 표에서 해당 항목만 지운다.

## 저장 위치

경로 규칙의 기준은 [AGENTS.md](../../../AGENTS.md)다. 여기 적힌 경로와 다르면 `AGENTS.md`를 따른다.

- 세션 인수인계는 `.claude/docs/{날짜}/{내용}.md`에 쓴다. `{날짜}`는 처음 쓴 날(`YYYY-MM-DD`), `{내용}`은 kebab-case 작업명이다.
- 다른 담당자가 고쳐야 할 내용은 인수인계에 섞지 않고 `.claude/handover/{날짜}/{내용}.md`에 전달 문서로 따로 쓴다. 형식은 [guided-commit](../guided-commit/SKILL.md) 7단계를 따르고, 인수인계에서는 그 전달 문서 경로를 가리킨다.
- 두 폴더는 Git에서 제외된다. 쓰기 전에 `git check-ignore -v {경로}`로 제외 여부를 확인하고, 제외되지 않으면 쓰지 않고 사용자에게 알린다.
- 현재 작업 색인은 아직 정하지 않았다 **(미정)**.
- 사용자가 파일로 남기지 않겠다고 하면 같은 템플릿으로 채팅에 출력한다.

## 절차

### 1. 기존 항목인지 먼저 확인한다

- 현재 작업 색인이 정해져 있으면 읽고, 지금 작업이 이미 있는지 본다. 색인이 없으면 `.claude/docs/` 아래 날짜 폴더에서 같은 작업의 기존 문서를 찾는다.
- **있으면 새 문서를 만들지 않는다.** 원본 문서를 열어 갱신한다. 날짜도 바꾸지 않는다. 옮기면 이전 세션이 남긴 경로가 끊긴다.
- 없으면 새 문서를 만든다. 파일 이름은 kebab-case 작업명으로 한다.
- 이어받은 작업인지 애매하면 임의로 판단하지 말고 사용자에게 어느 항목인지 확인한다.

### 2. 사실을 수집한다 - 기억으로 쓰지 않는다

문서에 적을 값은 전부 확인하고 쓴다.

- `git status`, `git log --oneline -5`, `git branch --show-current`: 커밋한 것, 커밋하지 않은 변경, 브랜치(`feature/{팀원이름}`).
- 이번 세션에 수정한 씬 이름, 신규 또는 수정한 ScriptableObject 경로, 신규 프리팹과 에셋 경로.
- 실제로 돌린 검증과 그 결과. 관찰하지 않은 것은 관찰했다고 쓰지 않는다.
- 확인할 수 없는 값(예: 인스펙터에서만 보이는 설정)은 값을 적지 말고 **재확인 방법**을 적는다.

### 3. 템플릿대로 쓴다

- [세션 인수인계](../../../docs/ai/05_SESSION_HANDOFF.md)의 템플릿(머리 필드와 8개 절)을 그대로 쓴다. 절을 임의로 늘리거나 줄이지 않는다. 담당 파트는 `{파트}`가 정해지지 않았으면 자리표시 그대로 둔다.
- 검증 상태 어휘와 L1~L3 수준은 [검증 플레이북](../../../docs/ai/03_VERIFICATION_PLAYBOOK.md)을 따른다. `완료(검증됨)`, `구현됨(미검증)`, `검증 대기`를 섞어 쓰지 않는다.
- 멀티플레이 등급(M0~M3)은 [멀티플레이 테스트 절차](../../../docs/ai/04_MULTIPLAYER_TEST_PROTOCOL.md)를 따른다.
- 관찰한 사실과 추정을 문장 단위로 구분한다. 추정에는 추정이라고 적는다.
- 7절 "다음 세션의 첫 행동"은 명령형으로, 실행 순서대로 적는다. "확인 필요" 같은 모호한 문장 대신 무엇을 어떻게 확인하는지 적는다.
- 6절 차단 조건에는 **누가 무엇을 해줘야 풀리는지**를 적는다.

### 4. 이 프로젝트에서 빠뜨리면 안 되는 것

| 항목 | 왜 |
|---|---|
| 수정한 씬 이름 | 다음 세션이 다른 씬을 열면 작업이 보이지 않는다 |
| 신규 ScriptableObject 경로 | 인스펙터에서 값을 넣어야 동작하는 경우가 많다 |
| 멀티플레이 검증 등급(M0~M3) | 신뢰도를 결정한다. 네트워크 변경인데 M2 미검증이면 반드시 명시하고, 인원 조건이 걸리면 `{최대 인원}`을 채웠는지 적는다 |
| 다른 파트에 요청한 인터페이스 | 답을 못 받으면 계속 막힌다 |
| 테스트용으로 되돌려야 할 설정 | 예: Build Settings 시작 씬, 테스트를 위해 바꾼 임시 값 |

### 5. 문서 안의 경로를 확인한다

- 저장소 문서로 가는 링크는 인수인계 문서의 실제 위치에서 계산한다. 이전 문서의 접두사를 그대로 복사하지 않는다.
- 저장소 밖에 저장하면 상대 링크 대신 저장소 루트 기준 경로(예: `docs/ai/05_SESSION_HANDOFF.md`)를 적는다.

### 6. 현재 작업 색인을 갱신한다

- 색인이 정해져 있으면 항목, 경로, 상태를 갱신한다. 색인이 아직 (미정)이면 이 단계를 건너뛰고 보고에 그렇게 적는다.
- **본문을 색인에 복사하지 않는다.** 상태 칸에는 지금 어디까지 됐고 무엇이 막혔는지만 한두 줄로 적는다.
- 끝난 항목은 색인에서만 지운다. 문서는 남긴다.

### 7. 사용자에게 보고한다

- 쓴 문서 경로와, 색인에서 무엇을 바꿨는지(또는 색인이 미정이라 건너뛰었는지) 알린다.
- 확인하지 못해 비워둔 칸이 있으면 무엇을 왜 못 채웠는지 명시한다.

## 하지 않는 것

- 확인하지 않은 값을 기억이나 추측으로 채우기
- 검증하지 않은 항목을 `완료(검증됨)`으로 적기
- 이미 있는 항목에 대해 오늘 날짜로 새 문서를 만들기 (원본을 갱신한다)
- 색인에 본문 복사하기
- 개인 기록을 Git에 커밋하거나, Git 제외가 확인되지 않은 저장소 경로에 쓰기. 저장소에 남겨야 하는 결정은 `docs/`에 따로 쓴다
- `AGENTS.md`에 정한 경로 밖에 개인 기록을 쓰기
- 인수인계를 쓰는 김에 코드나 설정을 함께 고치기. 이 스킬은 기록만 한다

## 공유 문서와 개인 기록의 경계

[문서 분류 기준](../../../docs/DOCUMENTATION_POLICY.md)을 따른다.

- 팀원에게 필요한 계약, 사용법, 담당자 인계는 `docs/`에 자립적으로 작성한다.
- 특정 실행자의 세션 기록, 개인 모델 선호, 개인 PC 설정, 계정과 비용 기록, 시행착오와 원시 증거는 개인 기록 영역에 둔다.
- `docs/` 문서가 개인 기록을 읽어야만 이해되는 구조를 만들지 않고, 개인 기록의 링크나 파일 경로를 공유 문서에 남기지 않는다. 필요한 공용 사실은 공유 문서 본문에 적고 코드와 공유 문서를 근거로 삼는다.
- 개인 기록끼리의 링크와 색인 포인터는 유지할 수 있다.
