# Meshy 모델 제작과 품질 개선

요청: $ARGUMENTS

실사에 가까운 3D 스타일화 판타지 모델을 제작한다. 신규 제작은 Meshy CLI 원본 생성 → Blender 가공 → 실제 AO/PBR → LOD → Unity 배치용 프리팹까지 진행한다. 기존 모델의 AO·재질 개선은 해당 원본에서 시작하고 변경의 영향을 받는 LOD와 프리팹까지 검증한다. 사용자가 원본 생성만 등 범위를 명시하면 그 범위를 따른다. 최종 화면의 원신풍 툰(2026-10-24 결정)은 후처리·VFX가 맡으므로 모델·재질을 툰용으로 바꾸지 않는다.

## 기준과 시작점

먼저 저장소 루트를 확인하고 아래 문서를 읽는다. 프로젝트 규칙의 정본은 이 문서들이며, 스킬에 적힌 요약보다 현행 정본을 우선한다.

- [아트 제작 기본 과정](../../../docs/unity/ART_ASSET_PRODUCTION_WORKFLOW.md): 스타일, AO/PBR, 셰이더, LOD, 산출물 기준.
- [씬·에셋 안전](../../../docs/unity/SCENE_AND_ASSET_SAFETY.md): 소유 범위, 경로, 원본 보관, GUID.
- [검증 플레이북](../../../docs/ai/03_VERIFICATION_PLAYBOOK.md): 실제 증거와 미검증 구분.
- 대상 선정 시 [모델 제작 목록](../../../docs/design/model-production-list.md), 기존 자산 확인 시 [공용 환경 에셋 목록](../../../docs/unity/SHARED_ENVIRONMENT_ASSET_CATALOG.md)을 필요한 부분만 읽는다.

대상·원화·용도·치수·고정 조립물인지 재조합 키트인지·캐릭터 리깅 필요 여부를 기존 자료에서 좁힌다. 결과를 바꾸는 핵심 정보만 질문한다. 이미 승인된 제작과 품질 보정은 반복 확인 없이 진행한다. 이 스킬은 추가 결제나 무제한 재생성을 허용하지 않는다.

## 1. 원본 확보

기존 Assets와 제작 원본을 먼저 확인한다. 회전·크기·재질 변경으로 해결되면 재사용한다. 규격이 중요한 벽·기둥·계단은 Blender에서 정확히 만들고, 자연물·독립 조형물은 Meshy 원본을 활용한다. Meshy 요청을 임의로 다른 생성 서비스로 바꾸지 않는다.

신규 Meshy 생성 시 [CLI 실행과 복구](references/meshy-cli.md)를 읽는다. 단일 물체 참조를 준비하고, 마을 지도 전체를 한 모델의 입력으로 넣지 않는다. 다각도 입력은 설치 CLI가 지원하는 전용 경로에서만 사용한다. 프롬프트에는 실루엣·재료·비율·용도를 담고 원화의 조명 효과를 재질 색으로 요구하지 않는다.

생성 입력·작업 ID·상태·실제 비용·출처를 보존한다. 실패나 타임아웃 후 기존 작업부터 조회하여 중복 과금을 막는다. 인증값은 출력·기록하지 않는다. 계정 플랜이나 입력 권리 미확인을 CC0·독점 소유로 표현하지 않는다.

다운로드 원본과 .blend는 Assets 밖의 Git 제외 작업 폴더에 보존하고 편집본을 분리한다. 개인 시안·상세 기록·렌더는 `.claude/docs/{처음 쓴 날짜}/`에 두며 이어지는 작업은 원래 폴더를 갱신한다.

## 2. Blender 형상 정리

Blender MCP 연결과 실행 버전을 확인한다. 연결할 수 없으면 설치된 실제 Blender의 background Python으로 가공할 수 있다. 둘 다 없으면 가공 단계를 미실행으로 남기고 생성만으로 완성됐다고 하지 않는다.

실제 미터 치수·피벗·축·스케일·재질 슬롯·UV·노멀을 확인한다. 중복 면·내부 면·작은 구멍·뒤집힌 면·융합된 부품을 고치되 원본 UV, 커스텀 노멀, 버텍스 컬러를 무조건 초기화하지 않는다. 개선 전후 실루엣을 같은 카메라로 비교한다. 리깅 모델은 웨이트·본·블렌드셰이프와 변형을 보존하고, 정적 모델 정리 절차를 그대로 적용하지 않는다.

## 3. 실제 AO와 PBR

아트 기본 과정 3장의 실제 베이크 절차를 적용한다. 다음 실수를 특히 방지한다.

- AO는 실제 형상에서 베이크하거나 검증된 버텍스 AO를 사용한다. BaseColor 명암 추출, 노이즈, 어두운 색 칠하기를 실제 AO로 보고하지 않는다. SSAO도 자산 AO를 대신하지 않는다.
- 베이크할 UV·이미지·활성 타깃·색 공간을 지정하고 고밀도→저밀도 투영에는 케이지/거리를 확인한다. 고유 AO와 겹친/타일링 UV의 대응을 먼저 해결한다.
- 독립 키트는 조각 자체의 local AO를 굽고 갤러리 이웃의 가림은 제외한다. 고정 조립물은 부품 사이 접촉 AO를 포함하고 조립 위치가 바뀌면 재베이크한다.
- Cycles AO 노드의 Only Local을 쓰려면 해당 출력을 Emission에 연결해 Emit 베이크한다. 일반 AO 베이크를 실행한 것만으로 노드 설정을 적용했다고 하지 않는다.
- 가림 거리·샘플·해상도·여백은 실제 크기와 게임 카메라에 맞춘다. 검은 번짐·UV 이음·과한 줄눈·얇은 면 자기 가림을 수정한다.
- BaseColor는 조명을 분리한 재료 색으로 만든다. 생성 색에 남은 그림자를 확인하고 AO를 중복 곱하지 않는다. 조명 제거 옵션의 존재만으로 제거 성공을 주장하지 않는다.
- Normal은 탄젠트 공간 방향과 요철을 검수한다. 단순 색의 밝기 차이를 높이로 오인해 과장하지 않는다. Roughness는 재료별 반사 폭을 조정하고 금속이 아닌 재료를 금속으로 만들지 않는다.

기본 URP Lit의 연결은 BaseColor sRGB, Normal은 Normal Map 임포트, 데이터 맵은 선형이다. Metallic은 R, Smoothness는 `1 - Roughness`를 A, AO는 G에 넣고 Smoothness 입력 채널과 배율을 확인한다. 맵을 공유 패킹할 때 실제 셰이더가 각 채널을 읽는지 확인한다. 기본 Lit에 별도 AO UV가 있다고 가정하지 않는다.

폴리지·Unlit 등은 실제 셰이더 입력에 맞춘다. 지원되는 버텍스 AO를 보존하거나 재질 특성상 AO를 생략할 때 이유를 적는다. 불투명 잎 모델에 임의 알파를 만들지 않는다. 플레이어를 가리는 환경물은 현행 아트 규칙의 Occlusion Fade 셰이더, 바닥은 바닥용 기준을 따른다.

## 4. LOD와 Unity 연결

화면 크기·실루엣·반복 배치 비용으로 LOD 개수와 감면 정도를 정한다. 감면 후 UV·노멀·재질 슬롯·버텍스 컬러를 확인하고 대응이 깨지면 재베이크한다. 리깅 모델은 각 LOD의 변형도 확인한다.

런타임 FBX·사용 텍스처·재질은 아트 규칙의 `Assets/01.Scripts/05.Art/{Characters,Environment,Props}/{에셋}/`에, 배치용 PF는 `Assets/02.Prefab/`의 해당 분류에 둔다. 임포트 치수와 루트 스케일을 실측하고 LODGroup·재질·용도별 Collider를 구성한다. 장식 Collider 생략은 이유를 남긴다. 에셋 이동·이름 변경은 Unity에서 하고 메타 GUID를 보존한다.

고해상도 원본과 베이크 중간물은 Assets 밖에 둔다. 런타임 해상도·압축·밉맵·CPU 읽기 복사·스트리밍을 확인한다. 파일 용량과 실제 로드된 텍스처 메모리를 구분하며 아틀라스 개수 감소를 메모리 절감으로 단정하지 않는다.

## 5. 검수와 결과

기존 씬을 변경하지 않는 임시 프리뷰부터 사용한다. 동일 노출·광원·프레이밍에서 원화/원본/수정본, AO 켬/끔을 비교한다. 중립 조명과 가능한 실제 게임 조명에서 앞·뒤·근거리·게임 거리·각 LOD를 확인한다. AO는 간접광에서도 확인하고 직사광에서 차이가 작다고 과하게 올리지 않는다. 검수 이미지가 비어 있으면 다시 촬영한다.

반복 모듈은 인접·2×2 배치를 확인한다. 실제 Unity 재질 참조·텍스처 채널·메타·누락 셰이더·신규 Console 진단을 확인하고 결함을 고친 뒤 재촬영한다. 정지 LOD 프리뷰를 연속 전환·보행·게임 성능 검증으로 보고하지 않는다.

개인 상세 기록에는 입력/원본/편집본 경로, 작업 ID와 실제 비용, 치수, LOD별 삼각형, AO 설정과 파일, 맵·셰이더, PF·충돌, 비교 이미지, 실제 검증과 미검증을 남긴다. 공유 모델 목록에는 경로·사용 조건·검증 범위를, [에셋 대장](../../../docs/licenses/ASSET_REGISTRY.md)에는 출처·권리 확인 상태를 남긴다. 저장소의 osk 결과 기록 지침도 따른다.

최종 답변은 배치용 PF와 비교 이미지, 개선 내용, 확인한 검증, 남은 제약을 간결하게 제시한다. PF·재질·AO·LOD가 빠졌으면 모델 제작 완료로 보고하지 않는다. 사용자가 명시적으로 제한한 범위의 완료와 전체 게임 사용 검증을 구분한다.
