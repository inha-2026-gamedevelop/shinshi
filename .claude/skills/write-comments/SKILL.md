# 주석 작성

## 언제 발동하나

사용자가 코드에 주석을 달아달라고 요청하면 발동한다. 규칙의 원본은 [코딩 컨벤션](../../../docs/coding-convention.md) 12장(주석)이다. 여기서는 그 규칙을 실제로 적용하는 절차만 다룬다. 두 문서가 어긋나면 코딩 컨벤션이 우선한다.

## 규칙 요약 (원본: 코딩 컨벤션 12장)

1. **꼭 필요한 곳에만.** 무엇을 위해 만든 것인지만 적는다. 코드를 읽어서 알 수 있으면 주석을 달지 않는다.
2. **"무엇"은 한 줄을 넘기지 않는다.** 길어지면 주석을 늘리지 말고 이름을 고치거나 메서드를 쪼갠다.
3. **"왜"는 길어도 된다.** 되돌리면 깨지는 이유, 다른 안을 버린 이유, 실측으로 뒤집힌 전제, 경계값의 근거는 여러 줄을 써서라도 남긴다. 길이의 근거는 "이걸 모르면 잘못 고친다"이지 친절함이 아니다.
4. **문서 위치를 적지 않는다.** 기획서 절 번호, 코딩 컨벤션 장 번호, 다른 파일 경로를 넣지 않는다. 근거가 필요하면 번호 대신 이유 자체를 적는다.
5. **키보드로 바로 치는 ASCII 기호만 쓴다.** 별표, 이모지, 장식 문자, 화살표(`->`로), 대시류(`-`로), 가운뎃점(`,`로), 수학 기호(`!=` `<=` `>=`로), 한자(한글로)를 쓰지 않는다. 주석뿐 아니라 코드 안의 모든 한국어 문자열(`Debug.Log`, `[Header]`, `[Tooltip]`, 예외 메시지 등)에 적용된다.
6. **한 줄 주석은 마침표 없이 짧은 구절로, 여러 줄 설명은 문장으로 쓴다.**
7. **XML 문서 주석은 `<summary>` 하나만 쓴다.** public API 설명에만 쓰고, 그 외(내부 로직, private 멤버, 판단 근거)는 일반 주석 `//`로 쓴다. `<remarks>`, `<see cref>`, `<c>`, `<inheritdoc/>`, `<param>`, `<returns>`, `<b>`는 쓰지 않는다. 다른 타입이나 멤버는 이름만 쓰고, 인터페이스 구현 쪽은 구현에만 있는 사정이 있을 때만 일반 주석을 단다.
8. **남은 작업은 TODO로 적극 남긴다.** `// TODO({팀원이름}): 할 일` 형식으로 담당자를 붙인다.
9. **적용 범위는 팀이 소유한 소스다.** Mirror, 외부 에셋, 생성 코드는 일괄 주석 정리에서 제외하고, 저작권과 라이선스 고지, 생성기, 린터, 컴파일러 지시문은 보존한다.

## 절차

1. 주석을 달 대상 코드를 읽고, 코드 자체가 이미 말하고 있는 것과 실제로 설명이 필요한 부분(왜 이렇게 했는지, 숨은 제약, 다음에 할 일)을 구분한다. 누락 여부는 줄 수가 아니라 외부 계약과 숨은 제약(서버 권위, 세션 수명, 재시도와 중복 방지, 스냅샷 확정 시점 등)을 기준으로 판단한다.
2. 코드가 이미 명확한 곳에는 주석을 추가하지 않는다. "주석을 달아달라"는 요청이 모든 줄에 주석을 달라는 뜻은 아니다. 필요 없는 곳은 비워두고, 왜 비웠는지 설명하지 않는다(그 설명 자체가 또 하나의 잉여 주석이 된다).
3. 대상이 public API(다른 파트나 팀원이 호출하는 메서드, 프로퍼티, 클래스)의 외부 계약이면 `/// <summary>`로, 내부 구현이나 판단 근거면 `//`로 작성한다.
4. 근거가 기획서나 다른 문서에 있더라도 **절 번호나 경로를 적지 않고 그 이유를 옮겨 적는다.** 문서가 개정되면 번호는 어긋나는데 주석은 따라 고쳐지지 않는다.
5. 미완성이거나 후속 작업이 필요한 지점을 발견하면 `// TODO({팀원이름}): 내용`을 남긴다. 이름은 코드를 작성 중인 사람 기준이다. 담당자를 모르면 사용자에게 묻는다.
6. 주석만 바꾸는 작업이면 실행 토큰, 전처리 지시문, 직렬화 필드, 문자열(정규식, URL 포함)을 건드리지 않는다. 화면 문구나 로그 문자열 정리는 별도 변경으로 분리한다. Python 등 다른 언어는 그 언어의 주석과 docstring 규칙을 따르고 C# XML 문법을 복사하지 않는다.
7. 작성 후 `git diff`로 다시 훑어서 아래를 점검하고 고친다.
   - 코드를 읽으면 알 수 있는 주석이 섞였는가
   - "무엇"을 설명하는 주석이 한 줄을 넘었는가
   - 문서 절 번호나 파일 경로가 들어갔는가
   - ASCII가 아닌 기호(화살표, 대시, 가운뎃점, 이모지 등)가 들어갔는가
   - 한 줄 주석이 마침표로 끝나는가
   - `<summary>` 외의 XML 태그가 들어갔는가
   - 주석 외의 코드가 바뀌었는가

```csharp
_health -= damage; // 체력 감소                              코드가 말하는 것을 반복
```
