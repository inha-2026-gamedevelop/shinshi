# 신시 문서 읽기 안내

> 기준일: 2026-10-07 · 문서 버전: 1.1 · 대상: 기획·클라이언트·서버·콘텐츠 제작자
> 기획 및 기술 설계 기준 문서다. 게임 코드·API·DB·통합 동작의 구현 완료를 의미하지 않는다.

2026-10-07 사용자 결정으로 전투 직업을 검사·마검사·미정 세 번째 직업으로 개편한다. 현재 설계는 일반 기술 8개·부적 효과 30개이며, 최종 3직업·12기술·45효과 목표에는 미정 직업의 4기술·15효과 예약이 포함된다. 외형은 P09를 유지한다. 현재 코드·저장 데이터의 무사/도술사/신령사와 신규 설계의 차이는 [캐릭터·애니메이션 개편](design/character-animation-design.md), 구규칙은 [기존 직업 설계 보존본](design/legacy-class-design.md)에서 확인한다.

## 3. 문서 간 기준

1. 사용자의 최신 결정이 요구사항을 정한다. 변경 시 관련 문서의 현재 본문을 함께 고친다.
2. 게임 규칙·밸런스의 설계 원본은 02와 연결된 기획 부록이다. 아직 게임 SO가 없으므로 문서 수치를 구현값으로 오인하지 않는다.
3. SO가 생기면 실제 실행값은 GameDB에서 확인하고 설계 목표와 차이를 기록한다. SO가 다르다는 이유로 기획 의도를 조용히 바꾸지 않는다.
4. 기술 계약은 03, 구체적 배치는 04가 담당한다. 기존 [네트워크 권위](unity/NETWORK_AUTHORITY.md)와 [서버·클라이언트 협업](unity/SERVER_CLIENT_WORKFLOW.md)의 승인된 경계를 따른다.
5. C# 스타일·네임스페이스·서버/클라 코드 분리 규칙은 [코딩 컨벤션](coding-convention.md)이 유일한 기준이다.
6. 코드·에셋의 존재와 기능·다인 검증 완료는 별개다. 증거 없는 작업을 05에서 완료로 바꾸지 않는다.
7. 담당·작업 ID·선행·일정·수용 기준은 05가 기준이다. 01 7장의 담당 범위와 어긋나거나 부록에 다른 날짜가 있으면 05와 01을 먼저 맞춘다.

## 5. 지금 남은 입력

- 미정 세 번째 직업의 무기·전투 역할·4기술·15부적과 사용 애니메이션 결정. 현재 8기술/30효과 설계만으로 최종 3직업 체험판 구성을 완성했다고 판정하지 않는다.
- 검사·마검사 클립 선정/타이밍·부적 조합 검증과 코드/SO/저장 데이터 이관. 현행 구현 ID와 새 설계 ID는 구분한다.
- 월백 2페이즈: 다른 담당자의 설계가 들어오면 패턴·전환·처치 조건을 통합한다. 현재 문서로 전체 보스 공략이 완성되었다고 판정하지 않는다.
- 외부 체험판용 실제 그래픽·애니메이션·효과음·컷신 자산과 라이선스 확인.
- 배포 환경의 계정 발급·접속 주소·서버 크기·측정용 PC 확정 및 실제 빌드 검증.
- 초기 수치의 재미·성장 속도·성능 검증. 정해 둔 수치가 적정하다는 실측은 아직 없다.
- 3인의 실제 가용 시간. 2주 일정의 실현 가능성 판정에 필요하다.
- 월백 2페이즈 설계 제공자와 수령 기한, 통합 브랜치 운영, 지연 시험의 패킷 손실 기준은 미정이다. 05 4·5장에 기록한다.

첫 보스 철각, 하드 난이도, 폐허·제단은 후속 제작 범위다. 유저 경매장과 1:1 거래는 이번 체험판에 포함한다(구현됨·실행 미검증, 제작 물약 거래만 후속). 이번 체험판에서 누락된 구현과 후속 범위를 구분한다.
