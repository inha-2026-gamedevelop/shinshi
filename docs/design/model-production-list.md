# 신시 — 3D 모델 제작 목록

> 기준일: 2026-10-01 · 상태: 제작 계획·원본 수량 제안과 시제품 현황
> 제작 흐름은 사용자 지정 **Meshy CLI 생성 → Blender 수정 → Unity 프리팹 생성·확인**이다.
> 실제 모델 생성·Blender 수정·게임 내 검증 완료를 뜻하지 않는다.

## 1. 목적과 기준

[컨셉아트 기록](concept-art.md)의 월백 전장(CA-01), 숲(CA-02), 신시 마을(CA-03·CA-04)을 제작 가능한 모델 단위로 나눈다. 공용 돌바닥(CA-05)과 부유석(CA-06)은 구조 참고로 사용한다. 공용 원본을 먼저 확보하고, 지역별 차이는 조립·형태 변형·재질·효과로 만든다.

공용 돌바닥(MOD-04)은 [PF_StoneCourtyardTile](../../Assets/02.Prefab/Environment/StoneCourtyard/PF_StoneCourtyardTile.prefab), 장식용 부유석(NAT-02 파생)은 [PF_FloatingRock](../../Assets/02.Prefab/Environment/FloatingRock/PF_FloatingRock.prefab)을 배치한다. 바닥은 6m 간격·이동 높이 Y=0, 부유석은 윗면 피벗·충돌 없는 배경 장식이다. 두 프리팹과 아래 PRP-01 석등은 AO/PBR·3LOD·에디터 프리뷰를 확인했으며 게임플레이·성능·빌드는 미검증이다. ARC-01 기와집·ARC-04 붉은 문·PRP-02 매다는 등, 지형 키트와 여성 외형은 아래 시제품 상태를 따른다. 그 밖의 신규 모델은 제작 계획이다.

모든 후속 모델은 [아트 제작 기본 과정](../unity/ART_ASSET_PRODUCTION_WORKFLOW.md)에 따라 목표 이미지·원화 대조, 실사에 가까운 3D 스타일화 판타지 재질, 실제 AO·노멀·거칠기 처리, LOD와 `02.Prefab/` 프리팹 생성·검증까지 진행한다. AO는 별도 사용자 요청 없이 기본 과정에 포함한다. 모델별 셰이더 지원과 재질 예외는 같은 문서에서 구분한다.

- **원본 수**는 서로 다른 기본 모델 수 제안이다. 맵 배치 수, Meshy 호출 수, 재시도 수와 다르다.
- **파생형**은 원본을 Blender에서 수정하거나 재질을 바꾼 모델이다. 지역마다 같은 물체를 새로 생성하지 않는다.
- **조립물**은 공용 부품으로 구성한 건물·다리·광장이다. 조립물마다 별도의 Meshy 원본을 요구하지 않는다.
- 표의 ID는 이 문서의 제작 항목을 식별한다. 게임 데이터 ID나 구현된 에셋 이름이 아니다.
- 모델의 재질·조명은 2026-10-01 최신 사용자 설명에 따라 **실사에 가까운 3D 스타일화 판타지**를 목표로 한다. 원화의 큰 형태·비례·실루엣과 판타지 색감을 따르고 실제 석재 균열·마모·이끼, 재료별 거칠기·노멀·PBR과 자연광에서 읽히는 디테일을 살린다. 앞선 실사 판타지 요청·3D 스타일화 확인·생성 시안·개별 모델 수치는 당시 이력으로 보존한다. 최종 색·건축 양식·별도 외형 기준은 [미술 기본안](experience-service.md)과 콘셉트의 미정 사항을 함께 확인하며 메시 밀도는 별도로 검증한다.
- 맵 규모·전투 경계는 [전투·전장 기준안](combat-design.md)을 따른다. 그림으로 규칙을 확정하지 않는다.

### 기존 모델 우선 확인

2026-10-01 작업 트리에서 `Assets/01.Scripts/05.Art/Environment/CherryTree/Models/SM_CherryTree.fbx`와 꽃·줄기 재질, 폴리지 셰이더를 확인했다. 꽃나무 항목은 기존 모델의 형태·크기·게임 카메라 적합성을 먼저 검토한 뒤 부족한 형태만 추가 제작한다.

기본 지형은 공용 부유석 한 원본을 변형한 Core/E/NE/NW/W/SW/SE 독립7조각 키트로 제작했다. 추가 녹색 상부판 없이 원래 암석·이끼 표면·공유PBR·자체AO7·3LOD·숨은 상단충돌을 사용한다. `Assets/01.Scripts/05.Art/Environment/VillageTerrain/{Models,Textures,Materials}/Chunks/`의28FBX·7AO·7재질과 [조립용7PF](../../Assets/02.Prefab/Environment/VillageTerrain/Chunks/)를 사용하며 [검수 갤러리](../../Assets/00.Scenes/Dev_FloatingIslandKit.unity)에서 각 조각을 확인한다. 사용자가 [빈 조립영역이 있는 Dev씬](../../Assets/00.Scenes/Dev_ShinshiVillageTerrain.unity) 등 작업 씬에서 배치하며 전체맵을 자동 조립하지 않는다. 이전 `PF_VillageTerrain` 통합시제품은 이력이고 현행 키트로 사용하지 않는다. Unity 임포트/참조/메타·고정화면·지정ray/강제LOD는 확인했으나 선택면용충돌이 모든가시면의 보행을 보장하지 않으며 실제접합·보행·연속LOD·게임플레이·성능/빌드는 미검증이다. 경계보존LOD의 메시비용은 [맵 성능 준비](../unity/MAP_PERFORMANCE_PREPARATION.md)에서 실측하고 상세 디자인/제작 기록은 개인 docs에 보관한다.

[폴리지 셰이더·재질 안내](../unity/VERTEX_COLOR_FOLIAGE_SHADER.md)는 에디터 임포트·프리뷰 확인과 씬·플레이 모드·빌드 미검증을 구분한다. 파일 존재를 게임 내 재사용 검증 완료로 취급하지 않는다. 외부 모델 패키지 설치 여부는 [에셋 대장](../licenses/ASSET_REGISTRY.md)에서 별도로 확인한다.

### 여성 모듈형 리깅 시제품 — 2026-10-01

사용자 요청으로 작업을 종료했다. **현행 외형은 사용자 거절(REJECT), 신규 UMA 외형 채택·코드 연동은 보류**다. 같은 날 UMA를 쓰지 않기로 해 UMA3 연동 에셋49개(`PlayerFemaleModular/UMA/`)는 삭제했고, 아래 UMA 관련 검증은 당시 기록으로만 남긴다. 기존 PF와 카탈로그·런타임 기본 선택은 유지했다. 아래 기술 검증은 최종 외형 승인을 뜻하지 않는다.

기존 외형에서 파생한 [PF_PlayerFemaleModular](../../Assets/02.Prefab/Characters/PlayerFemaleModular/PF_PlayerFemaleModular.prefab)를 제작했다. 런타임 모델·애니메이션·재질은 `Assets/01.Scripts/05.Art/Characters/PlayerFemaleModular/`에 있다. 후속 얼굴·손 국소 표면 정리에서 UV와 목·손목 경계를 보존하고, 수정한 몸·머리 쌍의 실제 AO와 탄젠트 노멀을 2K로 다시 베이크했다. 전용 `M_PlayerFemaleModular_Base.mat`는 `Textures/T_PlayerFemaleModular_Refined_AO.png`, `T_PlayerFemaleModular_Refined_Normal.png`를 사용하며 Normal Scale은 1이다. 24개 뼈의 공통 골격, `Hips` rootBone을 쓰는 머리·몸·눈꺼풀의 3LOD와 `Blink` 눈꺼풀 모프, 걷기·달리기 검토용 애니메이션을 포함한다. 후속 표면 정리 모델의 LOD별 전체 삼각형 수는 56,044 / 29,997 / 16,941이며 각 단계에 눈꺼풀 3,840삼각형이 포함된다. Unity Humanoid Avatar 유효성, Read/Write 켬, Optimize Game Objects 끔, 9개 스킨드 렌더러의 임포트·참조를 확인했다. 높이 1.7m는 개인 시제품 치수이며 공용 비례·게임 판정 크기를 확정하지 않는다.

눈꺼풀은 기존의 그려진 눈 위에 추가한 별도 사각형 메시로, 독립 안구·얼굴 관절 토폴로지 제작을 대신하지 않는다. 단계별 512px BaseColor·거칠기·MetallicSmoothness를 사용한다. 얼굴의 조각난 UV를 눈꺼풀에 늘여 적용하던 줄무늬를 전용 피부 아틀라스로 교정했으며, Unity에서 닫힌 형상으로 계산한 기하 노멀 델타를 별도 Mesh 에셋에 보존했다. FBX BlendShape Normals는 None이다. 얇고 움직이는 부품에 고정 AO를 붙이지 않고 별도 노멀 맵도 생략한다. 마지막 닫힌 접합 형상을 프리팹에 재적용한 Unity 표본에서 기존 줄무늬와 눈 틈 제거를 확인했다. 캐릭터 외형·변형 검토용이므로 Collider는 없고 검토용 Animator는 게임 이동을 구현하지 않는다.

마지막 표면·눈꺼풀 보정과 애니메이션 기준 교정을 적용한 Unity 수치 검사에서 세 LOD의 목 경계 위치·UV·웨이트·공유 bindpose 차이는 0, 경계 노멀 내적은 0.9999999 이상이었다. 중립·걷기·달리기·머리 회전·목 기울임의 총 15표본에서 목 틈 0, 세 LOD의 Blink `0→50→100→0` 변형·초기화를 확인했다. 실제 `SkinnedMeshRenderer.BakeMesh` 스냅샷 33장(걷기 16프레임 포함)을 저장하고 실제 Animator 클립 이름·경로·weight도 검사했다. 이 증거는 CPU 스키닝 표본 검증이며 GPU 스키닝 갱신·플레이어 루프 실행·성능 측정은 포함하지 않는다. 검증은 별도 PreviewScene에서 실행했고 활성 씬의 경로·dirty 상태와 기존 씬 파일을 보존했다.

Medium/Low의 검증은 마지막 노멀 변경 전 결과이며 변경 후 재실행하지 않았다. 수치 검사와 사용자에게 거절된 얼굴 인상을 구분한다.

초기 네이티브 합성의 광범위 삼각형 패치는 카메라가 직접 사용하지 않는 합성용 원본 텍스처의 streaming mip 선택으로 UV 조각 경계가 번진 문제였다. 같은 기하에 원본2K 비스트리밍 텍스처를 적용한 진단으로 구분하고, 관련13개 텍스처의 streamingMipmaps를 끈 저장 importer 설정으로 세 LOD에서 광범위 패치 제거를 확인했다. mipmaps와 압축은 유지하며 전신 BaseColor·색상 마스크의 최대 크기는2048, 눈꺼풀은512, AO/Normal/MetallicSmoothness는1024다. 전역 QualitySettings를 이 캐릭터 수정에서 변경하지 않았다. 편집기 텍스처 object bytes 확인은 Player 메모리나 성능 예산 측정이 아니다. 세 LOD의 강제 정지 표본이며 실제 게임 카메라/연속 LOD·성능은 별도 검증한다.

기존 UMA 패키지·전역 UMAAssetIndexer·런타임 아바타 코드·카탈로그는 이 아트 작업에서 수정하지 않았다. 새 에셋의 정식 등록/참조 로드, 검토 종족·레시피 선택, 생성 후 DNA·SharedColor·Blink 적용은 런타임 담당 코드에서 연결해야 한다. 검토 native 조립 높이 약1.986m와 원본 PF1.700m를 구분하고 전체 표시 크기 조절을 native bind/rest 변경으로 처리하지 않는다. 기존 기본 몸/안구/속옷을 현재 Body+Head+Eyelids의3슬롯에 중복 결합하지 않으며 헤어·의복에는 별도 fitting 검증이 필요하다.

달리기의 일부 원본 PF 표본에서 손과 몸이 겹쳐 동작 맞춤·클리핑 보정이 필요하다. 현행 UMA 외형은 사용자 거절이며 채택·코드 연동을 보류하고 종료했다. 실제 High native 걷기16phase는1.2초 클립·유효 Avatar/55 human 매핑/humanScale1.13814175·유한정점·토폴로지·목틈0·중립복원0을 확인했으나 바닥9/16실패, phase0.75 최대19.9607mm침투가 남았다. 임시 iKOnFeet 진단은 침투가 없어졌지만1phase의25mm 초과 들뜸으로 전체실패했고 저장 에셋/Controller를 바꾸지 않았다. 교정된 native 전용Walk는 저장하지 않았다. 마지막 노멀 변경 후Medium/Low 재검증도 미실행이다. 최종 리토폴로지·얼굴 아틀라스/눈꺼풀 품질, 전체 슬라이더·조합, 독립 안구·입·표정, native 손가락 포즈·극한 DNA, 직업별 헤어·장비, GPU 연속 재생·상태 전환·전 조합 클리핑, 게임플레이·성능·Windows 빌드·배포 검증은 미완료다. 상세 제작 기록·렌더는 개인 docs에 보존하고 [에셋 대장](../licenses/ASSET_REGISTRY.md#여성-베이스-외형-시제품)에 출처와 사용 조건을 남긴다.

### Tripo 공통 여성 몸체·귀여운 얼굴 첫 검토 묶음 — 2026-10-03

사용자 승인으로 공통 몸체에 직업별 의상·헤어와 얼굴 3종을 분리하는 제작 방식으로 전환했다. 첫 검토 묶음은 불투명 유니타드를 입은 공통 몸체와 귀여운 인상의 성인 여성 얼굴이다. 작업은 최대 Blender 4개, 결과 검토는 두 개씩 진행한다. 기존 Meshy/UMA 시제품과 별도 에셋이며, 공통 몸체에 포함된 기술 확인용 기본 머리는 최종 얼굴 3종에 추가하는 네 번째 얼굴이 아니다.

같은 에셋 루트의 `Warrior/Textures/` 3장은 이전 무사 전신의 중간 베이크 보존본이며 현재 공통 몸체 프리팹에 연결하지 않는다. 분리 의상용 최종 맵이나 무사 제작 완료 결과로 사용하지 않는다.

런타임 모델·재질·텍스처는 `Assets/01.Scripts/05.Art/Characters/PlayerFemaleTripo/CommonBody/`, `Heads/Cute/`에 있다. 조립 검토용은 [PF_FemaleCommonBody_Cute](../../Assets/02.Prefab/Characters/PlayerFemaleTripo/PF_FemaleCommonBody_Cute.prefab), 기술 몸체 검토용은 [PF_FemaleCommonBody](../../Assets/02.Prefab/Characters/PlayerFemaleTripo/PF_FemaleCommonBody.prefab), 머리 교체용 템플릿은 [PF_FemaleHeadCute](../../Assets/02.Prefab/Characters/PlayerFemaleTripo/PF_FemaleHeadCute.prefab)이다. 머리 템플릿의 renderer bones/rootBone은 조립 대상의 동일 rest 골격으로 다시 연결해야 한다. 실제 공유 52뼈·최대 4가중치·Humanoid Avatar와 3LOD를 구성했으며, 조립본의 LOD 삼각형 수는 75,993 / 43,508 / 24,167이다. 약 1.67m는 시제품 치수이며 공용 비례·게임 판정 크기나 최종 성능 예산을 확정하지 않는다.

High 형상의 부품별 실제 자체 AO와 기하 노멀을 베이크하고 피부·천의 거칠기를 구분한 2K BaseColor/Normal/PackedMAS를 사용한다. PackedMAS는 R 금속성, G AO, A smoothness이며 데이터 맵은 선형으로 임포트한다. 얼굴 세부와 몸체 LOD의 표면 반응을 검수하고, 새 목 연결부의 투영 아티팩트는 국소 노멀 보정으로 처리한다. AO를 BaseColor에 다시 곱하지 않는다. 실제 Unity URP 다각도·강제 정지 LOD 및 간접광 AO 검증을 상세 제작 기록에 연결한다.

Native 걷기·달리기 16 phase × 3LOD를 두 조립 변형에서 각각 96표본 확인했다. 비유한 정점은 0, 몸체·귀여운 머리 목 간격의 최대값은 약 35.184µm다. renderer bounds는 `rootBone` 공간에서 실제 변형 표본으로 구성하고, 저장된 3개 프리팹의 모델·맵·뼈·LOD·메타 참조와 중립 bounds를 검사했다. 모델/텍스처 Read/Write는 끄고 뼈 계층을 보존한다. 텍스처 6개의 Editor object memory 합계는 약 64.26MiB이며 Player/GPU VRAM 측정값은 아니다. 장식·외형 검토용이므로 Collider를 생략했으며 게임용 capsule/hitbox는 구현하지 않았다. 검증은 격리 PreviewScene에서 수행하고 당시 활성 개발 씬과 dirty 상태를 보존했다.

목 아래 BaseColor 색 경계를 보정하고, 몸체 Medium 3개·Low 4개 polygon의 UV를 국소 보정했다. 변경 후 실제 Unity URP 고정 LOD·다각도 18이미지와 3개 프리팹의 15개 SkinnedMeshRenderer·52뼈·3LOD·모델/맵 참조 및 중립 bounds를 확인했다. 일부 낮은 LOD 종아리 미세 자국과 옷깃 경계는 남아 있으며 전체 외형 통과로 판정하지 않는다. 원본과 변경 전 FBX는 개인 제작 기록에 보존했다.

상태는 **첫 묶음 외형 수정 중, 검토용**이다. 목 노멀 반사 문제는 Native 화면에서 교정됐으며 최종 외형 재검토가 남아 있다. 참조 Run의 맨발 바닥 침투가 최대 약 25.77mm 남아 신발·RootHeight·FootIK 보정이 필요하다. 나머지 얼굴 2종, 직업별 의상·헤어, 독립 안구·표정, 의복/머리 보조본과 실제 흔들림, GPU 연속 재생·LOD 전환·게임 카메라·성능·빌드·플레이어 연동은 미완료다. SecondaryMotion 코드의 EditMode 28/28 통과는 실제 의복·헤어 동작 완료를 뜻하지 않는다. 원본·입력·상세 기록·검토 렌더는 Git 제외 개인 docs에 보존하고 출처·권리 확인 조건은 [에셋 대장](../licenses/ASSET_REGISTRY.md#tripo-여성-공통-몸체얼굴직업-참조--2026-10-0203)을 따른다.

## 8. 제작 순서와 작업 기록

### 우선순위

1. **스타일 시험:** 바위·소나무·석등·기와집을 하나씩 준비하고 기존 벚꽃나무와 함께 게임 카메라에서 톤을 비교한다.
2. **공용 원본:** 자연물·건축·소품을 제작한다. 약초와 캐릭터는 담당 기능에 필요한 시점에 병행한다.
3. **Blender 부품·파생형:** 연결 규격과 재질을 맞추고 건물·다리·난간을 시험 조립한다.
4. **지역 구성:** 공용 모델로 신시·숲·월백 전장을 구성하고 대표 모델을 추가한다.
5. **장식 확장:** 화면 밀도·전투 가독성·성능을 확인한 뒤 추가 장식을 넣는다. 후속 지역 모델은 해당 제작 단계에서 진행한다.

이 순서는 환경 제작의 권장 순서이며 팀 일정·캐릭터 제작 선행을 대체하지 않는다.

### Meshy CLI → Blender → Unity

1. 항목 ID, 대상 크기, 필요한 시점, 참고 이미지·프롬프트를 준비한다. 맵 전체 그림은 분위기 참고로 사용하고 생성 입력은 개별 물체 중심으로 준비한다.
2. Meshy CLI로 원본을 생성하고 작업 ID·출력 파일·사용한 입력을 기록한다. 형상을 먼저 검토한 뒤 재질·텍스처를 정리한다.
3. Blender에서 불필요한 면·겹침·노멀·UV를 정리하고 부품을 분리하거나 재제작한다. 실제 미터 크기와 피벗을 맞춘다.
4. 원본에서 지역별 파생형을 만든다. 색·낡음·이끼·천·장식 차이는 재질과 부품으로 우선 해결한다.
5. Unity에서 재질·노멀·AO·LOD를 연결하고 용도에 맞는 충돌체를 설정한 뒤 `Assets/02.Prefab/{분류}/{에셋}/`에 `PF_` 프리팹을 만든다. 장식용 모델은 Collider를 생략할 수 있다. Blender 직접 제작 모델도 이 단계부터 같은 과정을 따른다.
6. 프리팹의 모델·재질·LOD 참조, `.meta`, 임포트·Console과 시각 결과를 확인한다. 모델 제작은 프리팹 생성까지 포함하며 게임 카메라 가독성·충돌·성능의 실제 검증 여부는 따로 기록한다. 씬·에셋·메타 작업은 [씬·에셋 안전 기준](../unity/SCENE_AND_ASSET_SAFETY.md)을 따른다.

공식 CLI는 텍스트·이미지 기반 생성, 리메시·리텍스처·다운로드를 제공한다. 실제 설치 버전의 명령·옵션은 [공식 CLI 문서](https://github.com/meshy-dev/meshy-cli)와 해당 명령의 도움말에서 확인한다. 이 문서는 CLI 설치·인증·생성 스크립트가 구현되었다는 뜻이 아니다.

## 9. 확인할 결정과 검증 상태

- 건축 시대감, 마을과 전장의 색 대비, 부유섬의 실제 설정 여부는 콘셉트 문서의 미정 사항이다.
- NPC 위치·출정 지점·생활 구역 입구·중앙 나무의 설정은 아직 확정하지 않는다.
- 월백 기둥의 충돌·전투 영역 포함 여부, 계단·사당의 전투 경계, 숲 지도와 끝 광장의 역할은 담당자 결정이 필요하다.
- 맵 담당 진욱, 보스 담당 기웅의 기존 역할은 [게임 기획서](../02-game-design.md)를 따른다. 이 문서가 새 제작 담당·기한을 배정하지 않는다.

| 확인 범위 | 현재 상태 |
|---|---|
| 콘셉트 4장과 기획 대조 | 목록 작성 근거로 사용. 미정 사항을 제작 확정과 구분 |
