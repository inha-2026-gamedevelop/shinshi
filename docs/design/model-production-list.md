> 기준일: 2026-10-01 · 상태: 제작 계획·원본 수량 제안과 시제품 현황
> 제작 흐름은 사용자 지정 **Meshy CLI 생성 → Blender 수정 → Unity 프리팹 생성·확인**이다.
> 실제 모델 생성·Blender 수정·게임 내 검증 완료를 뜻하지 않는다.

## 1. 목적과 기준

[컨셉아트 기록](concept-art.md)의 월백 전장(CA-01), 숲(CA-02), 신시 마을(CA-03·CA-04)을 제작 가능한 모델 단위로 나눈다. 공용 돌바닥(CA-05)과 부유석(CA-06)은 구조 참고로 사용한다. 공용 원본을 먼저 확보하고, 지역별 차이는 조립·형태 변형·재질·효과로 만든다.

공용 돌바닥(MOD-04)은 [PF_StoneCourtyardTile](../../Assets/02.Prefab/Environment/StoneCourtyard/PF_StoneCourtyardTile.prefab), 장식용 부유석(NAT-02 파생)은 [PF_FloatingRock](../../Assets/02.Prefab/Environment/FloatingRock/PF_FloatingRock.prefab)을 배치한다. 바닥은 6m 간격·이동 높이 Y=0, 부유석은 윗면 피벗·충돌 없는 배경 장식이다. 두 프리팹과 아래 PRP-01 석등은 AO/PBR·3LOD·에디터 프리뷰를 확인했으며 게임플레이·성능·빌드는 미검증이다. ARC-01 기와집·ARC-04 붉은 문·PRP-02 매다는 등, 지형 키트와 여성 외형은 아래 시제품 상태를 따른다. 그 밖의 신규 모델은 제작 계획이다.

모든 후속 모델은 [아트 제작 기본 과정](../unity/ART_ASSET_PRODUCTION_WORKFLOW.md)에 따라 목표 이미지·원화 대조, 실사에 가까운 3D 스타일화 판타지 재질, 실제 AO·노멀·거칠기 처리, LOD와 `02.Prefab/` 프리팹 생성·검증까지 진행한다. AO는 별도 사용자 요청 없이 기본 과정에 포함한다. 모델별 셰이더 지원과 재질 예외는 같은 문서에서 구분한다.

- **원본 수**는 서로 다른 기본 모델 수 제안이다. 맵 배치 수, Meshy 호출 수, 재시도 수와 다르다.
- **파생형**은 원본을 Blender에서 수정하거나 재질을 바꾼 모델이다. 지역마다 같은 물체를 새로 생성하지 않는다.
- **조립물**은 공용 부품으로 구성한 건물·다리·광장이다. 조립물마다 별도의 Meshy 원본을 요구하지 않는다.
- 표의 ID는 이 문서의 제작 항목을 식별한다. 게임 데이터 ID나 구현된 에셋 이름이 아니다.
- 모델의 재질·조명은 2026-10-01 최신 사용자 설명에 따라 **실사에 가까운 3D 스타일화 판타지**를 목표로 한다. 원화의 큰 형태·비례·실루엣과 판타지 색감을 따르고 실제 석재 균열·마모·이끼, 재료별 거칠기·노멀·PBR과 자연광에서 읽히는 디테일을 살린다. 앞선 실사 판타지 요청·3D 스타일화 확인·생성 시안·개별 모델 수치는 당시 이력으로 보존한다. 최종 색·건축 양식·별도 외형 기준은 [미술 기본안](experience-service.md)과 콘셉트의 미정 사항을 함께 확인하며 메시 밀도는 별도로 검증한다.
- 맵 규모·전투 경계는 [전투·전장 기준안](combat-design.md)을 따른다. 그림으로 규칙을 확정하지 않는다.

### 기존 모델 우선 확인

2026-10-01 작업 트리에서 `Assets/01.Scripts/05.Art/Environment/CherryTree/Models/SM_CherryTree.fbx`와 꽃·줄기 재질, 폴리지 셰이더를 확인했다. 꽃나무 항목은 기존 모델의 형태·크기·게임 카메라 적합성을 먼저 검토한 뒤 부족한 형태만 추가 제작한다.

기본 지형은 공용 부유석 한 원본을 변형한 Core/E/NE/NW/W/SW/SE 독립7조각 키트로 제작했다. 추가 녹색 상부판 없이 원래 암석·이끼 표면·공유PBR·자체AO7·3LOD·숨은 상단충돌을 사용한다. `Assets/01.Scripts/05.Art/Environment/VillageTerrain/{Models,Textures,Materials}/Chunks/`의28FBX·7AO·7재질과 [조립용7PF](../../Assets/02.Prefab/Environment/VillageTerrain/Chunks/)를 사용하며 [검수 갤러리](../../Assets/00.Scenes/Dev_FloatingIslandKit.unity)에서 각 조각을 확인한다. 사용자가 [빈 조립영역이 있는 Dev씬](../../Assets/00.Scenes/Dev_ShinshiVillageTerrain.unity) 등 작업 씬에서 배치하며 전체맵을 자동 조립하지 않는다. 이전 `PF_VillageTerrain` 통합시제품은 이력이고 현행 키트로 사용하지 않는다. Unity 임포트/참조/메타·고정화면·지정ray/강제LOD는 확인했으나 선택면용충돌이 모든가시면의 보행을 보장하지 않으며 실제접합·보행·연속LOD·게임플레이·성능/빌드는 미검증이다. 경계보존LOD의 메시비용은 [맵 성능 준비](../unity/MAP_PERFORMANCE_PREPARATION.md)에서 실측하고 상세 디자인/제작 기록은 개인 docs에 보관한다.

[폴리지 셰이더·재질 안내](../unity/VERTEX_COLOR_FOLIAGE_SHADER.md)는 에디터 임포트·프리뷰 확인과 씬·플레이 모드·빌드 미검증을 구분한다. 파일 존재를 게임 내 재사용 검증 완료로 취급하지 않는다. 외부 모델 패키지 설치 여부는 [에셋 대장](../licenses/ASSET_REGISTRY.md)에서 별도로 확인한다.

### 여성 베이스 외형 시제품 — 2026-10-01

CHR-01의 외형 검토용 [PF_PlayerFemaleBasePreview](../../Assets/02.Prefab/Characters/PlayerFemaleBasePreview/PF_PlayerFemaleBasePreview.prefab)를 제작했다. 런타임 모델·재질·텍스처는 `Assets/01.Scripts/05.Art/Characters/PlayerFemaleBasePreview/`에 있으며, 정적 `SM_` 모델의 3LOD는 52,003 / 26,001 / 12,999삼각형이다. UV·2K PBR 맵을 공유하고 실제 형상의 국소 AO를 베이크해 URP Lit에 연결했다. 높이 1.7m는 이 프리뷰의 임시 치수이며 공용 캐릭터 비례를 확정하지 않는다.

정적 외형 프리뷰이므로 Collider를 생략했다. 골격·스킨 웨이트·Animator·얼굴 모프가 없으며 목·손가락 주변의 소규모 비매니폴드 경계가 남아 있다. 얼굴 세부와 손 형상·표정 변형을 위한 리토폴로지도 필요하다. 별도 생성한 머리는 눈 크기·추가된 어깨·연결 규격 문제로 채택하거나 몸체에 조립하지 않았다. 생성 원본·입력·상세 제작 기록·렌더는 개인 docs에 보존하고, 출처·권리 확인 상태는 [에셋 대장](../licenses/ASSET_REGISTRY.md#여성-베이스-외형-시제품)에 기록한다.

Unity 임포트·모델/재질/LOD 참조·메타를 확인했고 이 정적 시제품의 당시 임포트 후 Console 오류·경고 조회는 0건이었다. 기존 씬을 바꾸지 않은 임시 프리뷰에서 중립 조명 다각도·얼굴/손 근접·강제 정지 LOD·AO 켬/끔을 시각 확인했다. 직사광 프리뷰의 AO 차이는 작았으며 간접광·PC/Mobile·실제 게임 밝기와 원본 색에 구워진 조명의 완전 제거는 미검증이다. 재질의 최종 품질, 실제 게임 카메라·연속 LOD·애니메이션 변형·얼굴 슬라이더·목 조립·게임플레이·성능·빌드는 이 정적 시제품의 미검증 범위이며 플레이 가능한 아바타 완료로 취급하지 않는다. 후속 모듈형 시제품도 이 시제품의 텍스처를 참조하므로 해당 폴더를 함께 보존한다.

### 여성 모듈형 리깅 시제품 — 2026-10-01

**외형 판정은 REJECT이며 신규 채택·코드 연동은 보류**다. UMA 미사용 결정으로 UMA3 연동 에셋은 삭제했다. 이 시제품은 현행 P09의 완료 근거가 아니다.

보존용 [PF_PlayerFemaleModular](../../Assets/02.Prefab/Characters/PlayerFemaleModular/PF_PlayerFemaleModular.prefab)의 모델·애니메이션·재질은 `Assets/01.Scripts/05.Art/Characters/PlayerFemaleModular/`에 있다. BaseColor·거칠기·MetallicSmoothness를 참조하는 `PlayerFemaleBasePreview/`도 함께 보존한다. 전용 재질은 Refined AO/Normal을 사용한다. AO는 수정한 몸·머리 쌍에 한정되며 다른 부품을 조립하면 [아트 기본 과정](../unity/ART_ASSET_PRODUCTION_WORKFLOW.md)에 따라 국소 AO와 조립 접촉 AO를 다시 검증·베이크한다.

24뼈 공통 골격과 `Hips` rootBone, 머리·몸·눈꺼풀 3LOD, Blink 및 검토용 걷기·달리기를 포함한다. 전체 삼각형 수는 56,044 / 29,997 / 16,941이다. 임포트는 Read/Write 켬·Optimize Game Objects 끔이며 1.7m는 시제품 치수다. 별도 눈꺼풀은 독립 안구·표정 토폴로지를 대신하지 않고 얇은 보조 면에 고정 AO·별도 노멀 맵을 생략한 예외다. Collider는 없으며 검토용 Animator는 게임 이동을 구현하지 않는다.

CPU 스키닝 표본과 정지 LOD의 기술 확인만 수행했다. 원본 PF 달리기의 손·몸 겹침과 보행 바닥 침투가 남았고, 삭제된 UMA 조립물의 보행 교정은 통과하지 않았다. 최종 얼굴·리토폴로지·전체 커스터마이징·직업별 장비·연속 GPU 재생·게임플레이·성능·빌드·배포는 미완료다. 출처·권리 조건은 [에셋 대장](../licenses/ASSET_REGISTRY.md#여성-베이스-외형-시제품)을 따른다.

### Tripo 공통 여성 몸체·귀여운 얼굴 첫 검토 묶음 — 2026-10-03

사용자 승인으로 공통 몸체에 직업별 의상·헤어와 얼굴 3종을 분리하는 제작 방식으로 전환했다. 첫 검토 묶음은 불투명 유니타드를 입은 공통 몸체와 귀여운 인상의 성인 여성 얼굴이다. 기존 Meshy/UMA 시제품과 별도 에셋이며, 공통 몸체에 포함된 기술 확인용 기본 머리는 최종 얼굴 3종에 추가하는 네 번째 얼굴이 아니다.

같은 에셋 루트의 `Warrior/Textures/T_FemaleWarrior_Tripo_*` 3장은 이전 무사 전신의 중간 베이크 보존본이며 현재 공통 몸체 프리팹에 연결하지 않는다. 새 분리 의상의 `T_FemaleWarrior_{BaseColor,Outfit_*,Hair_*,Boots_*}`와 구분하며, 이전 맵을 분리 의상 제작 완료의 근거로 사용하지 않는다.

런타임 모델·재질·텍스처는 `Assets/01.Scripts/05.Art/Characters/PlayerFemaleTripo/CommonBody/`, `Heads/Cute/`에 있다. 조립 검토용은 [PF_FemaleCommonBody_Cute](../../Assets/02.Prefab/Characters/PlayerFemaleTripo/PF_FemaleCommonBody_Cute.prefab), 기술 몸체 검토용은 [PF_FemaleCommonBody](../../Assets/02.Prefab/Characters/PlayerFemaleTripo/PF_FemaleCommonBody.prefab), 머리 교체용 템플릿은 [PF_FemaleHeadCute](../../Assets/02.Prefab/Characters/PlayerFemaleTripo/PF_FemaleHeadCute.prefab)이다. 머리 템플릿의 renderer bones/rootBone은 조립 대상의 동일 rest 골격으로 다시 연결해야 한다. 실제 공유 52뼈·최대 4가중치·Humanoid Avatar와 3LOD를 구성했다. 몸체의 UV 경계를 보존한 Blender 감면본은 41,740 / 22,956 / 18,782삼각형이며 Unity 임포트의 실제 인덱스 합계는 41,740 / 22,945 / 18,771이다. 현행 Cute 조립본의 Unity 합계는 85,785 / 45,866 / 29,732삼각형이고, 독립 머리 5부품 합계는 44,045 / 22,921 / 10,961이다. Low는 초기 몸체 목표 12,522삼각형보다 늘렸고 게임 성능 예산의 통과를 뜻하지 않는다. 약 1.67m는 시제품 치수이며 공용 비례·게임 판정 크기나 최종 성능 예산을 확정하지 않는다.

High 형상의 부품별 실제 자체 AO와 기하 노멀을 베이크하고 피부·천의 거칠기를 구분한 2K BaseColor/Normal/PackedMAS를 사용한다. PackedMAS는 R 금속성, G AO, A smoothness이며 데이터 맵은 선형으로 임포트한다. 얼굴 세부와 몸체 LOD의 표면 반응을 검수하고, 새 목 연결부의 투영 아티팩트는 국소 노멀 보정으로 처리한다. AO를 BaseColor에 다시 곱하지 않는다. 실제 Unity URP 다각도·강제 정지 LOD 및 간접광 AO 검증을 상세 제작 기록에 연결한다.

Native 걷기·달리기 16 phase × 3LOD, 96표본을 최종 Cute 조립본에서 재확인했다. 비유한 정점은 0, 공통 몸체·귀여운 머리의 목 간격 최대값은 약 35.184µm다. 몸체·머리·좌우 안구·좌우 속눈썹을 같은 52뼈에 연결했고 모든 15얼굴 renderer의 Blink와 3피부 renderer의 표정을 실제 프리팹에서 바인딩했다. 3LOD의 정면·양쪽 quarter·중간/좌우 Blink·Smile/Frown/BrowRaise 42개 실제 Unity URP 캡처와 몸체/조립본 18개 캡처를 확인했다. 피부 원본 BaseColor와 목 색은 보존했다. FBX의 54개 모프 기본값은 0이며, 속눈썹의 잘못된 후방 정점을 수정해 눈꺼풀 앞면에 연결했다. 중립 노멀과 Normal 맵은 유지하고, 임포트/재계산한 모프 노멀에서 재현된 각진 띠와 삼각 음영을 피하기 위해 Blend Shape Normals를 None으로 사용한다. 이 설정은 변형 시 노멀 델타를 쓰지 않는 품질 조건이며 완전한 모프 노멀 재구성을 검증한 것은 아니다. URP Lit의 안구 IOR/coat 표현도 Blender 재질의 근사다. 속눈썹은 얇은 불투명 갈색 기하이므로 UV·AO 텍스처를 생략하고 기본 occlusion 1을 사용한다.

renderer bounds는 `rootBone` 공간의 실제 걷기·달리기와 얼굴 변형 표본을 합치고 5mm 여유를 넣었다. 저장 후 걷기·달리기 96포즈를 다시 평가한 678회 메시 검사에서 저장 bounds 밖 정점은 0이었다. 저장된 3개 프리팹의 39개 SkinnedMeshRenderer·52뼈·3LOD·모델/맵/재질·메타 참조와 중립 bounds를 재검사했다. 모델/텍스처 Read/Write와 offscreen skin 갱신은 끄고 뼈 계층을 보존한다. 12개 텍스처의 Editor object memory 합계는 약 104.51MiB이며 Player/GPU VRAM 측정값은 아니다. 장식·외형 검토용이므로 Collider를 생략했으며 게임용 capsule/hitbox는 구현하지 않았다. PreviewScene에서 검증하고 활성 Bootstrap 씬과 dirty=false 상태를 보존했다. 몸체 Low의 과한 감면에서 생긴 큰 삼각 음영은 UV seam 6,672개를 보호하고 감면을 완화해 교정했다. 원본과 이전 실패 후보·FBX·캡처는 개인 제작 기록에 보존했다.

위 검증은 v28 첫 묶음의 기술적 조건부 통과 기록이다. 2026-10-04 후속에서 Cute 두상의 과한 후두부와 이마·정수리의 꺾임을 교정하고 실제 AO·Normal을 다시 베이크했다. 머리카락을 숨긴 정면·측면과 직업별 헤어를 결합한 3LOD 화면을 각각 확인했다. 원화 90% 유사도는 객관적으로 인증하지 않았으며 최종 스타일의 사용자 확인은 남아 있다. 눈은 URP Complex Lit의 specular workflow로 갈색 홍채의 회색빛을 줄였고, 기존 BaseColor·Normal·AO와 재질 GUID를 보존했다. 1픽셀 선형 float SpecularSmoothness는 base F0 0.004와 smoothness 140/255를 저장한다. coat는 URP 고정 IOR에 맞춘 근사이며 Blender의 모든 시야각 반사와 동등하다는 뜻은 아니다.

현행 머리는 `Heads/Cute/RuntimeMeshes/SourceMorphs/88efd188/`의 검증된 메시 15개를 사용한다. Unity가 작은 FBX 표정 델타를 제거하는 문제를 피하기 위해 저장 프레임은 10000, 델타는 원본의 100배이며 표현 코드의 논리 가중치 0~100은 유지한다. Head·CommonBody_Cute·세 직업의 저장 프리팹 모두 같은 메시, 이름별 52뼈, 54개 표정 기본값 0, Blink 15개와 피부 표정 subset 3개를 연결했다. 실제 Source 대조와 Bake 표본은 20µm 이내이며 renderer bounds에 중립과 각 표정의 논리 가중치 100을 포함했다. FBX의 임베디드 머리 메시를 바로 조립하면 이 저장 표정 교정이 적용되지 않는다. 표정 normal/tangent 델타는 0인 품질 조건을 유지하며 Source의 변형 노멀과 렌더링 동등성을 인증하지 않는다.

분리 의상과 헤어·신발·목은 `Warrior/`, `Taoist/`, `Spiritcaller/`에 배치했다. 조립본은 [PF_FemaleWarrior_Cute](../../Assets/02.Prefab/Characters/PlayerFemaleTripo/PF_FemaleWarrior_Cute.prefab), [PF_FemaleTaoist_Cute](../../Assets/02.Prefab/Characters/PlayerFemaleTripo/PF_FemaleTaoist_Cute.prefab), [PF_FemaleSpiritcaller_Cute](../../Assets/02.Prefab/Characters/PlayerFemaleTripo/PF_FemaleSpiritcaller_Cute.prefab)다. 실제 자체 AO·Normal·PackedMAS, 3LOD, 유효한 Humanoid Avatar와 보조본 27/31/33개를 연결했고, 3직업×3LOD×정지·걷기·달리기 54장 및 최종 얼굴·헤어 27장을 Native URP로 확인했다. 직업별 삼각형 합계는 무사 106,997/60,341/33,030, 도술사 107,177/60,334/32,766, 신령사 103,048/58,105/31,667이다. 신령사 Medium 헤어의 Source 대응 노멀 5개는 별도 runtime 메시로 교정했다. 신령사 헤어 확대 화면의 각진 판과 거친 끝은 기존 Source에도 남아 있어 외형 품질은 조건부다. 목은 검은 유니타드 UV의 별도 피부 재질이며 도술사·신령사의 동일 UV/형상에만 자체 AO를 공유한다. 조립 전체 접촉 AO와 구분한다.

저장 5프리팹의 메시·이름별 스킨·재질·3LOD·Blink 참조 검사와 캐릭터 EditMode 88/88을 확인했다. 관련 텍스처의 Editor object memory 합계 약 623.48MiB는 Player 메모리·VRAM·성능 예산 측정값이 아니다. 장식·외형 프리팹에는 게임플레이 Collider를 넣지 않았고 실제 Player·FootIK/Controller·게임 카메라·연속 LOD·지속 보조본 물리·M2/M3·빌드·성능은 미검증이다. 나머지 얼굴 2종은 후속 범위다. 상세 기록·실패 이력·검토 렌더는 Git 제외 개인 docs에 보존하고 출처·권리 확인 조건은 [에셋 대장](../licenses/ASSET_REGISTRY.md#tripo-여성-공통-몸체얼굴직업-참조--2026-10-0203)을 따른다.

팔 리깅 추가 검증에서 무사 Avatar가 원래 메시의 rest 자세를 Humanoid 기준으로 사용해 공통 몸체와 팔꿈치 각도가 달라지는 결함을 재현했고, 공통 calibrated 52뼈의 Humanoid 기준을 실제 세 직업 importer에 반영했다. Generic 최종 rest, 원래 메시·named weights·bindpose·보조본 계층은 유지한다. 무사·도술사는 기존 실제 팔 포즈와 새 실제 스킨의 144개 비교에서 최대 차이 약 0.963µm, 양수 영향 누락 0을 확인했다. 이 비교의 몸체 포즈 대상은 High이며 하위 몸체는 rest·named skin·bindpose 대조로 검증했다. 세 직업 Native 걷기·달리기 표본에서 팔·소매가 따라가는 것도 확인했다. 120/162도 극단 굽힘의 천 접힘 경고는 남아 있으며 모든 동작의 무관통 검증을 뜻하지 않는다. Avatar 변경 뒤에는 기존 FootSupportProfile의 식별·보정값과 동작 검증 결과를 재사용하지 않는다.

표현 연결 코드는 `Assets/01.Scripts/05.Art/Characters/PlayerFemaleTripo/Runtime/`에 구현했다. BlinkView는 지정한 얼굴·안구·속눈썹 LOD의 같은 모프를 적용·복원하고 표정은 피부 renderer subset에 적용한다. PresentationView는 이동 소스와 전투 상태를 읽어 Animator 파라미터와 시각 자식 회전만 갱신하며 게임플레이 루트는 쓰지 않는다. 소유 예측 소스는 `TravelledDistance` 누적 이동량과 비배율 시간으로 속도를 구하고 위치 차분·보정 거리를 읽지 않는다. 원격·Host에는 아직 공개 이동 속도 소스가 없어 사용 불가능한 표본과 유효한 정지 속도 0을 구분한다. SecondaryMotionBinding은 실제 스킨 참조가 있는 추가본을 연결한다. 7개 EditMode 테스트 클래스의 88건은 실제 Test Runner에서 모두 통과했다. 재활성화 2건은 콜백 초기화 본문 단위 검사이며 실제 PlayMode lifecycle의 증거는 아니다.

발 IK의 원래 위치 전용 구현은 격리 PlayMode 콜백 194회에도 연속 맨발 침투가 약 −29.54→−45.32mm로 악화돼 실패했다. 현재 FootIkView/FootSupportMath/직렬화 FootSupportProfile은 실제 맨발 스킨 지지점 2,573개와 최대 4가중치·52 bindpose로 발바닥을 재구성하고 Avatar별 발 목표 위치·회전 매핑으로 침투하는 발만 올린다. 별도 최소 Unity 프로젝트에서 PlayMode 2/2·EditMode 6/6, Walk/Run 448콜백·3LOD 1,344메시 표본을 확인했다. 동일 phase·루트 불변·비유한 정점 0, 비활성 발의 기하 변화 0이며 전체 표본의 최저 높이는 약 −29.448mm에서 LOD별 +0.0144 / +0.0105 / +0.6946mm로 바뀌었다. 실제 Assets에 같은 코드를 반영한 후 88건 통과와 프로필 바인딩·직렬화 데이터·참조 재연결도 확인했다. 독립 코드 검수는 조건부 통과다. 이 결과는 지정한 맨발·Avatar·클립·평면에 한정된다. 실제 Player·FootIK 프리팹/Controller 연결, 신발용 지지점 재작성, 경사·다른 클립·다수 캐릭터의 CPU/GC·게임·멀티플레이·Player 빌드 검증은 남아 있다. 관련 없는 메인 씬이나 Controller는 저장하지 않았다.

## 8. 제작 순서와 작업 기록

### 우선순위

1. **스타일 시험:** 바위·소나무·석등·기와집을 하나씩 준비하고 기존 벚꽃나무와 함께 게임 카메라에서 톤을 비교한다.
2. **공용 원본:** 자연물·건축·소품을 제작한다. 약초와 캐릭터는 담당 기능에 필요한 시점에 병행한다.
3. **Blender 부품·파생형:** 연결 규격과 재질을 맞추고 건물·다리·난간을 시험 조립한다.
4. **지역 구성:** 공용 모델로 신시·숲·월백 전장을 구성하고 대표 모델을 추가한다.
5. **장식 확장:** 화면 밀도·전투 가독성·성능을 확인한 뒤 추가 장식을 넣는다. 후속 지역 모델은 해당 제작 단계에서 진행한다.

이 순서는 환경 제작의 권장 순서이며 팀 일정·캐릭터 제작 선행을 대체하지 않는다.

### Meshy CLI → Blender → Unity

1. 항목 ID, 대상 크기, 필요한 시점, 참고 이미지·프롬프트를 준비한다. 맵 전체 그림은 분위기 참고로 사용하고 생성 입력은 개별 물체 중심으로 준비한다.
2. Meshy CLI로 원본을 생성하고 작업 ID·출력 파일·사용한 입력을 기록한다. 형상을 먼저 검토한 뒤 재질·텍스처를 정리한다.
3. Blender에서 불필요한 면·겹침·노멀·UV를 정리하고 부품을 분리하거나 재제작한다. 실제 미터 크기와 피벗을 맞춘다.
4. 원본에서 지역별 파생형을 만든다. 색·낡음·이끼·천·장식 차이는 재질과 부품으로 우선 해결한다.
5. Unity에서 재질·노멀·AO·LOD를 연결하고 용도에 맞는 충돌체를 설정한 뒤 `Assets/02.Prefab/{분류}/{에셋}/`에 `PF_` 프리팹을 만든다. 장식용 모델은 Collider를 생략할 수 있다. Blender 직접 제작 모델도 이 단계부터 같은 과정을 따른다.
6. 프리팹의 모델·재질·LOD 참조, `.meta`, 임포트·Console과 시각 결과를 확인한다. 모델 제작은 프리팹 생성까지 포함하며 게임 카메라 가독성·충돌·성능의 실제 검증 여부는 따로 기록한다. 씬·에셋·메타 작업은 [씬·에셋 안전 기준](../unity/SCENE_AND_ASSET_SAFETY.md)을 따른다.

공식 CLI는 텍스트·이미지 기반 생성, 리메시·리텍스처·다운로드를 제공한다. 실제 설치 버전의 명령·옵션은 [공식 CLI 문서](https://github.com/meshy-dev/meshy-cli)와 해당 명령의 도움말에서 확인한다. 이 문서는 CLI 설치·인증·생성 스크립트가 구현되었다는 뜻이 아니다.

## 9. 확인할 결정과 검증 상태

- 건축 시대감, 마을과 전장의 색 대비, 부유섬의 실제 설정 여부는 콘셉트 문서의 미정 사항이다.
- NPC 위치·출정 지점·생활 구역 입구·중앙 나무의 설정은 아직 확정하지 않는다.
- 월백 기둥의 충돌·전투 영역 포함 여부, 계단·사당의 전투 경계, 숲 지도와 끝 광장의 역할은 담당자 결정이 필요하다.
- 맵 담당 진욱, 보스 담당 기웅의 기존 역할은 [게임 기획서](../02-game-design.md)를 따른다. 이 문서가 새 제작 담당·기한을 배정하지 않는다.
