# 신시 — 3D 모델 제작 목록

> 기준일: 2026-10-01 · 상태: 제작 계획·원본 수량 제안과 시제품 현황
> 제작 흐름은 사용자 지정 **Meshy CLI 생성 → Blender 수정 → Unity 프리팹 생성·확인**이다.
> 실제 모델 생성·Blender 수정·게임 내 검증 완료를 뜻하지 않는다.

## 1. 목적과 기준

[컨셉아트 기록](concept-art.md)의 월백 전장(CA-01), 숲(CA-02), 신시 마을(CA-03·CA-04)을 제작 가능한 모델 단위로 나눈다. 공용 원본을 먼저 확보하고, 지역별 차이는 조립·형태 변형·재질·효과로 만든다.

모든 후속 모델은 [아트 제작 기본 과정](../unity/ART_ASSET_PRODUCTION_WORKFLOW.md)에 따라 목표 이미지·원화 대조, 실사에 가까운 3D 스타일화 판타지 재질, 실제 AO·노멀·거칠기 처리, LOD와 `02.Prefab/` 프리팹 생성·검증까지 진행한다. AO는 별도 사용자 요청 없이 기본 과정에 포함한다. 모델별 셰이더 지원과 재질 예외는 같은 문서에서 구분한다.

- **원본 수**는 서로 다른 기본 모델 수 제안이다. 맵 배치 수, Meshy 호출 수, 재시도 수와 다르다.
- **파생형**은 원본을 Blender에서 수정하거나 재질을 바꾼 모델이다. 지역마다 같은 물체를 새로 생성하지 않는다.
- **조립물**은 공용 부품으로 구성한 건물·다리·광장이다. 조립물마다 별도의 Meshy 원본을 요구하지 않는다.
- 표의 ID는 이 문서의 제작 항목을 식별한다. 게임 데이터 ID나 구현된 에셋 이름이 아니다.
- 모델은 3D 스타일화를 기준으로 하되, 최종 색·건축 양식·세부 형태는 [미술 기본안](experience-service.md)과 콘셉트의 미정 사항을 함께 확인한다.
- 맵 규모·전투 경계는 [전투·전장 기준안](combat-design.md)을 따른다. 그림으로 규칙을 확정하지 않는다.

### 기존 모델 우선 확인

2026-10-01 작업 트리에서 `Assets/01.Scripts/05.Art/Environment/CherryTree/Models/SM_CherryTree.fbx`와 꽃·줄기 재질, 폴리지 셰이더를 확인했다. 꽃나무 항목은 기존 모델의 형태·크기·게임 카메라 적합성을 먼저 검토한 뒤 부족한 형태만 추가 제작한다.

[폴리지 셰이더·재질 안내](../unity/VERTEX_COLOR_FOLIAGE_SHADER.md)는 에디터 임포트·프리뷰 확인과 씬·플레이 모드·빌드 미검증을 구분한다. 파일 존재를 게임 내 재사용 검증 완료로 취급하지 않는다. 외부 모델 패키지 설치 여부는 [에셋 대장](../licenses/ASSET_REGISTRY.md)에서 별도로 확인한다.

## 2. 공용 자연물

| ID | 모델 | 원본 수 제안 | 제작 방법 | 재사용·변형 |
|---|---|---:|---|---|
| NAT-01 | 둥근 바위·각진 바위·길쭉한 바위 | 3 | Meshy → Blender 정리 | 세 지역 공용. 회전·크기·이끼 재질 변형 |
| NAT-02 | 절벽 바위 덩어리 | 2 | Meshy → Blender 연결면 정리 | 숲 절벽, 월백 기반, 마을 섬 가장자리 조합 |
| NAT-03 | 곧은 소나무·굽은 소나무 | 2 | Meshy → 줄기·잎 정리 | 숲, 월백 배경, 마을 외곽 |
| NAT-04 | 작은 꽃나무·굽은 큰 꽃나무 | 2 | 기존 벚꽃나무 우선 검토, 부족분 생성 | 마을 주변과 월백 사당 공용 |
| NAT-05 | 단풍나무 | 1 | Meshy → 잎·가지 정리 | 숲의 색상 변화, 잎 재질로 계절 변형 |
| NAT-06 | 마른 고목 | 1 | Meshy → Blender 정리 | 숲, 후속 폐허·제단 |
| NAT-07 | 낮은 수풀·관목 | 2 | Meshy 초안 또는 Blender 제작 | 지면 채우기, 잎 색·높이 변형 |
| NAT-08 | 채집용 약초 | 2 | Meshy 초안 또는 Blender 제작 | 채집 노드 반복, 채집 후 형태는 파생형 |

자연물은 총 15개 원본 후보이며, 기존 모델을 채택하면 신규 생성량이 줄어든다. 약초 2종 제안은 생활 약초 노드 12개의 배치 규칙과 별개다. 약초의 실제 종·명칭을 새 게임 규칙으로 정하지 않는다.

나무는 줄기·가지와 잎·꽃을 분리하여 수정한다. 잎은 알파 클립 재질과 반복 가능한 텍스처 구성을 검토하고, 기존 모델의 버텍스 컬러 AO가 필요한 경우 편집·내보내기 과정에서 보존한다.

## 3. 공용 건축 원본과 Blender 부품

### 3.1 Meshy 원본 후보

| ID | 모델 | 원본 수 제안 | Blender 수정 | 재사용처 |
|---|---|---:|---|---|
| ARC-01 | 작은 기와집 | 1 | 지붕·벽·기둥·문을 분리하거나 원본을 참고해 규격 부품 재제작 | 마을 주택·상점·작업장, 월백 사당, 후속 폐허 |
| ARC-02 | 작은 초가집 | 1 | 지붕·벽 분리, 높이·길이 변형 | 마을 주택·생활 구역, 후속 폐허 |
| ARC-03 | 정자 지붕·장식 | 1 | 기둥·바닥은 규격 부품 조립 | 마을 연못·외곽 쉼터 |
| ARC-04 | 붉은 기둥 문 | 1 | 폭·높이·낡음 변형 | 마을 문, 숲 입구 파생형, 후속 제단 |

건축 원본은 총 4개 후보다. 건물의 한쪽 면만 정상인 결과를 완성 부품으로 취급하지 않고, 뒤쪽·안쪽·바닥과 분리 가능 여부를 Blender에서 확인한다. 기와 양식의 시대감이 미정이므로 처음부터 모든 건물의 세부 장식을 고정하지 않는다.

### 3.2 Blender에서 규격 제작할 부품

| ID | 부품 | 필요한 형태 | 조립·재사용 |
|---|---|---|---|
| MOD-01 | 목조 기둥·보·벽·문 | 기둥, 가로 보, 벽판, 문틀·문짝 | 공용 건물의 확장·변형 |

| MOD-03 | 돌담·목책 | 직선·모서리·끝 부품 | 마을 담장·숲 경계·폐허 |
| MOD-04 | 돌바닥·원형 광장 | 반복 바닥, 원형 구역·가장자리 | 신시 중앙 광장·월백 전장 |
| MOD-05 | 돌계단 | 직선·넓은 계단, 시작·끝 부품 | 건물·광장·다리 접근로 |

부품 간격·연결면·피벗·크기 기준은 첫 시험 조립에서 정한다. 반복 연결에 정확도가 필요한 부품은 Blender에서 직접 제작하거나 Meshy 원본을 참고해 재제작한다. 공용 돌·목재·기와·천 재질을 우선 사용한다.

## 5. 지역 대표 모델과 조립물

| ID | 지역·대상 | 제작 방법 | 중복 생성 방지·확인 사항 |
|---|---|---|---|
| LOC-01 | 신시 중앙 거대 꽃나무 | 별도 대표 원본 1개 후보 → Blender 수정 | 기존 꽃나무를 먼저 검토. 비단 띠·등은 공용 부품. 신단수 설정은 미정 |

| LOC-03 | 신시 대장간 화덕 | 별도 원본 1개 후보 | 건물은 ARC-01 변형. NPC 배치와 상호작용 위치는 미정 |
| LOC-04 | 신시 푸른 차양 가게 | ARC-01·MOD-10 조립 | 같은 건물을 재생성하지 않음 |
| LOC-05 | 월백 결계 기둥 | 별도 원본 1개 후보 → Blender 분리 | 그림의 6개는 반복 배치. 내부 구슬·천·빛을 분리하고 충돌 여부 확인 |
| LOC-06 | 월백 작은 사당 | ARC-01·MOD-05·PRP-05 조립 | 꽃나무는 NAT-04 공유. 접근 공간의 전투 포함 여부 미정 |
| LOC-07 | 월백 원형 전장·절벽 기반 | MOD-04·NAT-02로 Blender 구성 | 이동 전장 지름 36m 기준, 장식·계단·난간 범위는 별도 확인 |
| LOC-08 | 숲 입구 목조 문 | ARC-04 변형 또는 MOD-01 조립 | 목재 재질·장식 변경 |
| LOC-09 | 숲 모닥불·돌무더기 | NAT-01·장작 조립 | 불꽃은 효과, 원본 추가 생성 불필요 |

별도 대표 원본은 LOC-01·03·05의 3개 후보다. LOC-02 큰 지붕의 추가 원본과 부품 제작량은 여기에 포함하지 않는다.

2~5장의 기본 원본 후보는 **자연물 15 + 건축 4 + 소품 10 + 대표 모델 3 = 32개**다. 이는 기존 모델·Blender 직접 제작으로 대체하기 전의 계획 수량이며, 캐릭터·규격 부품·추가 장식·후속 모델은 제외한다. 확정 비용이나 Meshy 작업 횟수로 사용하지 않는다.

| ID | 모델 | 제작 시기·조건 |

CA-02는 긴 이동 경로와 폐허·제단으로 보이는 공간이 이어진 그림이다. 현재 체험판의 숲 이동 영역은 32m×32m이며, 폐허·제단·철각은 후속 범위다. 그림 전체를 체험판 필수 맵으로 만들거나 숲 끝 원형 광장을 월백 전장과 같은 장소로 확정하지 않는다.

## 6. 캐릭터·장비 모델 별도 목록

이 절은 콘셉트 그림의 직접 관찰 항목이 아니라 [게임 기획서](../02-game-design.md)와 [생활·서비스 기본안](experience-service.md), [전투 기본안](combat-design.md)에서 도출한 제작 후보다. 환경 원본 32개와 합산하지 않는다.

| CHR-07 | 후속 캐릭터 | 철각, 풍백·우사·운사 | 후속 전투·이야기 장면 요구가 정해진 뒤 판단 |
| CHR-08 | 장비·휴대 소품 | 직업별 무기, 필요 시 부적·물약 용기 | 무기 외형은 별도 결정. 등급마다 새 모델을 자동으로 요구하지 않음 |

캐릭터는 Meshy 생성 후 관절 주변 토폴로지·스킨 웨이트·리깅·애니메이션 변형을 확인한다. 사람의 목표 비례는 미술 기본안의 약 5.5~6등신을 참고한다. 꼬리·소매·머리카락처럼 움직이는 부위는 정적 소품과 검수 기준을 구분한다.

## 7. 모델 생성과 분리할 효과 작업

| 요소 | 제작 방향 | 필요한 메시 |
|---|---|---|
| 폭포·계류·연못 | 물 셰이더·파티클 | 단순 표면·폭포 면을 필요에 따라 Blender 제작 |
| 구름·안개·원경·달 | 배경·스카이·효과 | 표현 방식에 따른 단순 메시 또는 배경 이미지 |
| 광장 법진·문양 | 데칼·텍스처·셰이더 | 바닥 메시와 분리하여 조절 |
| 불꽃·여우불·구슬 빛·포털 | 파티클·발광·셰이더 | 기둥·문 프레임은 모델, 효과는 별도 |
| 꽃잎·연기 | 파티클·단순 카드 메시 | 필요 시 기존 꽃잎 메시 활용 |
| 바닥 낙엽·꽃잎·이끼 | 텍스처·데칼·단순 메시 조합 | 전투 화면에서 읽히는 수준으로 제작 |

등의 따뜻한 빛과 결계의 푸른빛은 같은 모델에 효과·재질을 바꿔 사용한다. 장식 법진·소환물·꽃잎의 밝기가 공격 예고를 가리지 않도록 게임 카메라에서 확인한다.

## 8. 제작 순서와 작업 기록

### 우선순위

1. **스타일 시험:** 바위·소나무·석등·기와집을 하나씩 준비하고 기존 벚꽃나무와 함께 게임 카메라에서 톤을 비교한다.
2. **공용 원본:** 자연물·건축·소품을 제작한다. 약초와 캐릭터는 담당 기능에 필요한 시점에 병행한다.
3. **Blender 부품·파생형:** 연결 규격과 재질을 맞추고 건물·다리·난간을 시험 조립한다.
4. **지역 구성:** 공용 모델로 신시·숲·월백 전장을 구성하고 대표 모델을 추가한다.
5. **장식 확장:** 화면 밀도·전투 가독성·성능을 확인한 뒤 추가 장식을 넣는다. 후속 지역 모델은 해당 제작 단계에서 진행한다.

이 순서는 환경 제작의 권장 순서이며 팀 일정·캐릭터 제작 선행을 대체하지 않는다.

### Meshy CLI → Blender → Unity

1. 항목 ID, 대상 크기, 필요한 시점, 참고 이미지·프롬프트를 준비한다. 맵 전체 그림은 분위기 참고로 사용하고 생성 입력은 개별 물체 중심으로 준비한다.
2. Meshy CLI로 원본을 생성하고 작업 ID·출력 파일·사용한 입력을 기록한다. 형상을 먼저 검토한 뒤 재질·텍스처를 정리한다.
3. Blender에서 불필요한 면·겹침·노멀·UV를 정리하고 부품을 분리하거나 재제작한다. 실제 미터 크기와 피벗을 맞춘다.
4. 원본에서 지역별 파생형을 만든다. 색·낡음·이끼·천·장식 차이는 재질과 부품으로 우선 해결한다.
5. Unity에서 재질·노멀·AO·LOD를 연결하고 용도에 맞는 충돌체를 설정한 뒤 `Assets/02.Prefab/{분류}/{에셋}/`에 `PF_` 프리팹을 만든다. 장식용 모델은 Collider를 생략할 수 있다. Blender 직접 제작 모델도 이 단계부터 같은 과정을 따른다.
6. 프리팹의 모델·재질·LOD 참조, `.meta`, 임포트·Console과 시각 결과를 확인한다. 모델 제작은 프리팹 생성까지 포함하며 게임 카메라 가독성·충돌·성능의 실제 검증 여부는 따로 기록한다. 씬·에셋·메타 작업은 [씬·에셋 안전 기준](../unity/SCENE_AND_ASSET_SAFETY.md)을 따른다.

공식 CLI는 텍스트·이미지 기반 생성, 리메시·리텍스처·다운로드를 제공한다. 실제 설치 버전의 명령·옵션은 [공식 CLI 문서](https://github.com/meshy-dev/meshy-cli)와 해당 명령의 도움말에서 확인한다. 이 문서는 CLI 설치·인증·생성 스크립트가 구현되었다는 뜻이 아니다.

### 모델별 기록 항목

아래는 목록에서 확인할 요약 항목이다. 상세 제작 결과·AO/PBR·프리팹 검증의 기록 템플릿과 문서 위치는 [아트 제작 기본 과정의 인수 노트](../unity/ART_ASSET_PRODUCTION_WORKFLOW.md#6-모델별-짧은-인수-노트)를 정본으로 따른다.

| 항목 | 기록 내용 |
|---|---|
| 제작 식별 | 목록 ID, 원본/파생형/조립물 구분, 참고 원본 ID |
| 입력·생성 | 참고 이미지 출처, 프롬프트, Meshy 작업 ID, 생성일 |
| 결과 파일 | Blender 원본, 내보낸 모델·텍스처, Unity 에셋·`02.Prefab/` 프리팹 경로 |
| 수정 사항 | 분리·재제작·UV·재질·리깅 변경 |
| 검증 | Blender 정적 확인, Unity 화면·애니메이션·성능 확인 결과 |
| 상태 | 기존 모델 검토/입력 준비/생성 완료/Blender 수정 완료/프리팹 생성 완료/Unity 확인 대기/검증됨 |

키·토큰·계정 비밀값은 기록하지 않는다. 폴리곤·텍스처·LOD 예산은 게임 화면 시험 후 정하며, 이 문서에서 검증되지 않은 성능 수치를 확정하지 않는다.

## 9. 확인할 결정과 검증 상태

- 건축 시대감, 마을과 전장의 색 대비, 부유섬의 실제 설정 여부는 콘셉트 문서의 미정 사항이다.
- NPC 위치·출정 지점·생활 구역 입구·중앙 나무의 설정은 아직 확정하지 않는다.
- 월백 기둥의 충돌·전투 영역 포함 여부, 계단·사당의 전투 경계, 숲 지도와 끝 광장의 역할은 담당자 결정이 필요하다.
- 맵 담당 진욱, 보스 담당 기웅의 기존 역할은 [게임 기획서](../02-game-design.md)를 따른다. 이 문서가 새 제작 담당·기한을 배정하지 않는다.

| 확인 범위 | 현재 상태 |
|---|---|
| 콘셉트 4장과 기획 대조 | 목록 작성 근거로 사용. 미정 사항을 제작 확정과 구분 |
| 기존 벚꽃나무·재질·셰이더 | 파일 존재와 관련 안내 확인. 이번 작업에서 화면·성능 재검증 안 함 |
| 원본 수량·재사용 관계 | 제작 제안. 기존 에셋 채택·직접 제작에 따라 조정 |
| Meshy CLI 설치·인증·생성 | 이번 문서 작성에서 미실행 |
| Blender 수정·Unity 적용·리깅·성능 | 이번 문서 작성에서 미실행 |

문서의 링크·공백 등 정적 확인과 실제 모델 품질·게임 실행 검증을 구분한다. 완료 판정은 [검증 플레이북](../ai/03_VERIFICATION_PLAYBOOK.md)을 따른다.
