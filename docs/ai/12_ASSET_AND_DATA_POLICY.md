# 에셋 · 데이터 취급 정책

> 이 프로젝트에서 외부로 나가면 안 되는 것과, 라이선스를 지켜야 하는 것을 정한다.

---

## 1. 외부 AI에 넣어도 되는 것

| 등급 | 내용 |
|---|---|
| 문제없음 | 자신이 작성한 코드, 기획 문서, 공개 API 사용법, 일반 기술 질문 |
| 주의 | 팀원의 코드 (본인 확인 후), 미공개 기획 내용 |
| 금지 | 구매 에셋의 원본 코드 · 모델 · 텍스처, 계정 정보, API 키 |

---

## 2. 구매 에셋

**구매 에셋의 원본 파일을 외부 AI에 업로드하지 않는다.**

Unity Asset Store 등에서 구매한 에셋은 각각의 EULA가 있고, 대부분 재배포를 금지한다.
AI에 코드를 올리는 것이 재배포인지는 다툼의 여지가 있으므로, 안전한 쪽을 택한다.

### 대신 이렇게 한다

- 사용법 질문 → 공식 문서를 인용하거나 API 이름만 언급
- 오류 해결 → 에러 메시지와 자신의 호출 코드만
- 통합 방법 → 자신이 작성한 래퍼 코드만

---

## 3. 라이선스 관리

외부 출품 · 배포에 대비해 [에셋 대장](../licenses/ASSET_REGISTRY.md)에 아래 항목과 설치 버전·실제 경로를 기록한다. 유료 에셋은 `Assets/99.ThirdParty/`에서 분류하며 패키지 단위로 Git에서 제외한다.

```markdown
| 에셋명 | 제작자 | 출처 | 라이선스 | 상업 이용 | 취득일 |
|---|---|---|---|---|---|
| {에셋명} | {제작자} | Unity Asset Store | Asset Store EULA | {가능/불가} | {YYYY-MM} |
```

무료 · 오픈소스 패키지도 기록한다. 네트워크 라이브러리 Mirror는 설치할 때 이 표에 라이선스 원문 기준으로 추가한다.

### 특히 확인할 것

| 항목 | 왜 |
|---|---|
| Sketchfab 모델 | CC 라이선스 종류에 따라 상업 이용 불가한 것이 많다 |
| 무료 폰트 | 한글 폰트는 상업 이용 조건이 제각각이다 |
| 사운드 · 음원 | 샘플 · 효과음 모음은 출처 확인이 특히 필요하다 |
| AI 생성 에셋 | 사용한 도구의 상업 이용 약관을 확인한다 |

**"무료"와 "상업 이용 가능"은 다르다.** 반드시 라이선스 원문을 확인한다.

## 3.5 아트 원본은 저장소에 넣지 않는다

Blender 원본(`.blend`), 텍스처 원본, 굽기 스크립트 같은 대용량 작업 원본은 `Assets/` 밖에 두고 저장소에 커밋하지 않는다. **(도입 예정)** 원본 폴더를 처음 만들 때 `.gitignore`에 등록한다.

| | |
|---|---|
| 왜 빼나 | 대용량 원본은 GitHub 저장소 권장 한도를 쉽게 넘는다. LFS로도 팀원 전원이 클론마다 받아야 한다. 한 번 커밋하면 되돌려도 이력에 남아 저장소가 영구히 무거워진다 |
| 실행에 지장 없나 | 없다. `Assets/` 밖이면 Unity가 읽지 않는다. 씬 · 프리팹 · 머티리얼이 이 경로를 참조하지 않게 한다 |
| 게임에 들어가는 것 | `Assets/` 아래에 임포트된 결과물이며 **이쪽은 커밋한다** |
| 언제 원본이 필요한가 | 텍스처를 다시 굽거나 모델을 고칠 때. 그때는 원본 보관처에서 받아온다 |

**원본 보관처:** 아직 정하지 않았다(미정). 정하면 여기에 경로를 적는다.
그때까지 원본이 한 사람의 로컬에만 있다면, 다른 팀원은 아트 원본을 손보기 전에 그 담당자에게 먼저 물어본다.

## 4. 코드에 남기면 안 되는 것

- 개인 계정 정보, 이메일
- API 키, 토큰
- 로컬 절대 경로 (`C:/Users/이름/...`)
- 테스트용 하드코딩된 IP 주소

민감한 설정은 Git 제외 파일(예: `.env`, `*.local`)에 둔다. 이 항목과 키 파일(`*.key`, `*.pem` 등)은 `.gitignore`에 등록되어 있다.

---

## 5. 스크린샷 · 영상

발표나 이슈에 첨부할 때 확인한다.

- 다른 창의 내용이 보이는가
- 파일 경로에 실명이 있는가
- 알림 팝업이 찍혔는가

---

## 6. 유출을 발견하면

1. 추가 전송을 즉시 중단한다
2. 무엇이 · 언제 · 어디로 나갔는지 사실과 추정을 구분해 보고한다
3. 커밋 히스토리에 들어갔으면 {팀장}과 상의한다 (혼자 히스토리 재작성하지 않는다)
4. 키나 토큰이면 즉시 폐기하고 재발급한다
