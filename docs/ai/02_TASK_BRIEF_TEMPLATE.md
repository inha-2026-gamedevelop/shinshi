# 작업 브리프 템플릿

> 작업의 이유와 실행 계약을 함께 제공해 범위 이탈, 과잉 구현, 근거 없는 완료 주장을 줄인다.

---

## 사용 규칙

- 결과와 제약을 적고 세부 구현 순서는 실행자에게 맡긴다.
- 간단한 조회나 오타 수정에는 필요한 필드만 쓴다.
- 불명확한 값은 추측하지 말고 `{{미정}}`으로 표시한다.
- 분석만 요청할 때는 수정 금지를 명시한다.
- 검증 수준은 [검증 플레이북](03_VERIFICATION_PLAYBOOK.md)에 맞춰 정한다.

---

## 복사용 템플릿

```markdown
# {{작업명}}

## 배경
- 이 작업이 필요한 이유: 
- 근거 문서: {{기획서 · 기술 설계 문서의 경로와 절}}

## 산출물
- 최종 형태: 
- 이번에 포함: 
- 후속으로 미룸: 

## 영향 범위
- 담당 파트: {파트}
- 수정할 씬: {{담당 개발 씬}}
- 네트워크 영향: 없음 / 서버 권위 추가 / 동기화 변경
- 밸런스 데이터 영향: 없음 / ScriptableObject 신규 / 기존 값 변경
- 다른 파트와 충돌 가능성: 

## 범위
- 읽기: 
- 수정 가능: 
- 제외: 

## 제약
- 반드시 지킬 것: 
- 사전 승인 필요: 
- 스코프 잠금 위반 여부: {{스코프 잠금 항목에 해당 없음 확인}} (잠금 항목은 기획서 확정 후 정한다)

## 완료 기준
- [ ] 
- [ ] 
- [ ] 검증 결과와 미검증 항목을 구분해 보고한다

## 검증
- 위험도: 낮음 / 보통 / 높음 / 치명적
- 최소 수준: L1 / L1+L2 / L1+L2+L3
- 멀티플레이 등급: M0 / M1 / M2 / M3
- 관찰할 성공 신호: 
- 중단·롤백 조건: 
```

## shinshi 프로젝트 예시

게임 중립 예시다. 폴더 번호 `{NN}`과 클래스 이름은 가정이며, 실제 값은 [코딩 컨벤션](../coding-convention.md)과 파트 확정 결과를 따른다.

```markdown
# 바닥 아이템 획득

## 배경
- 플레이어가 바닥에 떨어진 아이템을 주워 소지품에 넣는 기본 상호작용. 여러 플레이어가 같은 아이템을 동시에 주우려 할 수 있다
- 근거 문서: (작성 예정) 기획서의 아이템 절

## 산출물
- 최종 형태: DroppedItem 컴포넌트와 ItemDefinitionSO ScriptableObject
- 이번에 포함: 획득 요청, 서버의 거리·중복 판정, 획득 결과 동기화
- 후속으로 미룸: 획득 연출과 UI 알림

## 영향 범위
- 담당 파트: {파트}
- 수정할 씬: {{담당 개발 씬}}
- 네트워크 영향: 서버 권위. 획득 판정은 서버, 결과를 모든 클라이언트에 동기화
- 밸런스 데이터 영향: ItemDefinitionSO 신규 생성
- 다른 파트와 충돌: 소지품 저장 경로가 다른 파트와 겹칠 수 있음 → 인터페이스 협의 필요

## 범위
- 읽기: Assets/01.Scripts/00.Common/, Assets/01.Scripts/01.Network/
- 수정 가능: Assets/01.Scripts/{NN}.Item/, Assets/09.Data/Item/
- 제외: Assets/01.Scripts/01.Network/ (읽기만), Assets/01.Scripts/98.Servers/ ({팀장}에게 요청), 통합 씬

## 제약
- 반드시 지킬 것: 획득 성공 여부는 서버가 판정하고 클라이언트는 요청과 표시만
- 사전 승인 필요: 새 네트워크 멤버(Command·SyncVar)가 필요하면 {팀장}에게 요청
- 스코프 잠금 위반: 해당 없음

## 완료 기준
- [ ] 획득 가능 거리 안에서만 획득 요청이 수락된다
- [ ] 두 플레이어가 동시에 요청해도 한 명만 획득한다
- [ ] 획득된 아이템이 모든 클라이언트에서 사라진다
- [ ] 수치(획득 거리 등)가 전부 ScriptableObject에 있다
- [ ] 검증 결과와 미검증 항목을 구분해 보고한다

## 검증
- 위험도: 높음 (공유 상태, 네트워크)
- 최소 수준: L1 + L2 + L3
- 멀티플레이 등급: M2
- 관찰할 성공 신호: 모든 클라이언트에서 같은 아이템이 같은 플레이어에게만 들어가고, 바닥에서 동시에 사라짐
- 중단 조건: 한 아이템이 두 플레이어에게 들어가면 즉시 중단하고 판정 경로 재검토
```

## 분석 전용 변형

분석만 필요하면 아래 제약을 추가한다.

```text
읽기 전용으로 조사하라. 어떤 파일도 수정하지 마라.
원인, 선택지, 영향, 근거를 보고한 뒤 중지하라.
수정은 별도 승인된 작업으로 분리하라.
```

## 작성 전 점검

- 목적이 구현 절차가 아니라 관찰 가능한 결과로 적혔는가?
- 수정 가능 범위와 제외 범위가 겹치지 않는가?
- 완료 기준마다 확인 방법이 있는가?
- 네트워크 영향과 씬 소유권을 검토했는가?
- 스코프 잠금 항목을 건드리지 않는가?
