# 다단계 작업 절차

> 여러 세션 · 여러 단계에 걸친 작업의 완료 기준과 안정점을 정한다.

---

## 1. 언제 적용하나

- 한 세션에 끝나지 않는 작업
- 멀티플레이 접속 테스트를 중간에 기다려야 하는 작업
- 다른 파트의 인터페이스 확정을 기다리는 작업
- 여러 마일스톤에 걸쳐 이어지는 시스템

---

## 2. 단계 나누는 기준

**각 단계가 끝날 때마다 프로젝트가 실행 가능해야 한다.**

컴파일이 깨진 채로 세션을 넘기지 않는다. 다음 세션이나 다른 팀원이 아무것도 못 하게 된다.

| 좋은 단계 경계 | 나쁜 단계 경계 |
|---|---|
| 플레이어 이동 동기화까지 (공격은 다음) | 클래스 절반만 작성 |
| 적 1종 완성 (나머지 종류는 다음) | 여러 종을 각각 30%씩 |
| 서버 로직 완성, UI는 다음 | 서버와 UI를 동시에 절반씩 |

---

## 3. 단계 기록 형식

```markdown
### Phase N — {{결과}}

- 상태: 완료(검증됨) / 구현됨(미검증) / 검증 대기 / 차단됨
- 산출물: 
- 검증: L? / M?
- 다음 단계 선행 조건: 
```

---

## 4. 안정점

각 단계 종료 시 아래를 확보한다.

- [ ] 컴파일 통과, 콘솔 에러 0
- [ ] 해당 단계의 완료 정의를 충족
- [ ] 브랜치에 커밋됨 (또는 미커밋 사유가 기록됨)
- [ ] 다음 세션 기록 또는 팀 전달 문서를 [인수인계](05_SESSION_HANDOFF.md)·[문서 분류](../DOCUMENTATION_POLICY.md)에 따라 작성
- [ ] 다음 단계의 첫 행동이 명시됨

---

## 5. 개발 일정과의 연결

일정은 아직 정하지 않았다(미정). 정하면 아래 표를 채운다.

| 마일스톤 | 기간 | 단계 종료 기준 |
|---|---|---|
| 프로토타입 | {기간} | **{최대 인원} 접속 상태에서 핵심 조작(이동 · 공격 등)이 동작** |
| 개발 | {기간} | 단계별 시스템이 M2 검증 통과 |
| 마감 | {날짜} | 신규 기능 없음, 버그 수정과 밸런스만 |
| 버퍼 | {기간} | 지연 흡수용. 계획대로면 새 작업을 시작하지 않는다 |

**프로토타입 종료 시점에 다인 접속이 안 되면 이후 일정 전체가 위험하다.**
다른 기능을 미루더라도 이것부터 확보한다.

---

## 6. 중단 시

- 어디까지 됐고 무엇이 막혔는지 [인수인계](05_SESSION_HANDOFF.md)에 기록
- 커밋하지 않은 변경이 있으면 그 사실과 이유를 명시
- 다음 세션의 첫 행동을 명령형으로
- 멀티플레이 테스트 대기 중이면 **무엇을 확인해야 하는지 체크리스트를 남긴다**
