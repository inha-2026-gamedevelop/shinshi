# 피해 숫자 타격 애니메이션

기존 `Assets/01.Scripts/02.Combat/Player/View/DamageNumberPool.cs`의 소유자 전용 숫자 표시에 적용된다. `DamageNumberBinder`가 소유자의 피해 피드백 이벤트를 받아 기존 `Show(in DamageFeedback)`를 호출한다. 피해량·치명타/도트 표식·RPC·서버 판정은 변경하지 않는다.

2026-10-31 작업 트리에서 일반 숫자는 `Resources/T_DamageBrushDigits.png`의 붓글씨 숫자를 사용하고, 치명타는 같은 숫자를 노란색으로 칠하며 `Resources/T_DamageCriticalInk.png`를 뒤에 표시한다. 두 리소스는 `Assets/01.Scripts/05.Art/HitFeedback/Resources/`에 있다. 극단적으로 큰 값은 기존 TMP 축약 표기로 표시하며 치명타 먹은 유지한다. 리소스가 없으면 숫자는 TMP로 대체한다. 이 변경의 실제 서버 타격·빌드·다인 검증은 아직 하지 않았다. 아래 2026-10-26 수치와 결과는 당시의 기록이다.

## 동작과 조정

숫자는 기본 크기의 0.3배에서 시작해 정규화 수명 0.07에서 2.1배까지 커진 뒤 기본 크기로 돌아온다. 처음 0.35초는 알파 1을 유지한 뒤 나머지 수명에 페이드한다. 가볍게 기울어진 글자는 초기 30% 수명 안에 수직으로 돌아오고, 위로 110px·좌우 48px을 기준으로 이동한다. 연속 숫자의 좌우 방향은 번갈아 분산된다. 월드 기준 표시 원점은 기존 서버 좌표에 고정하고 카메라 투영은 매 LateUpdate 갱신한다.

치명타는 노란 숫자와 먹 배경에 크기 배율 1.35를 적용한다. 일반 크기는 40, 치명타는 62, 전체 수명은 0.95초다. 일반 범위의 피해량은 붓글씨 숫자 이미지로 표시하며, 극단적으로 큰 값은 TMP 축약 표기로 대체한다.

| Inspector | 기본값 | 용도 |
|---|---|---|
| `_lifetimeSeconds`, `_risePixels` | 0.95초, 110px | 전체 수명과 상승 거리 |
| `_readableSeconds` | 0.35초 | 투명해지기 전 선명하게 유지하는 시간 |
| `_popScale` | 정규화 수명 곡선 | 0.3→2.1→0.9→1.1→1배 크기 변화 |
| `_sidePixels`, `_tiltDegrees` | 48px, 14° | 좌우 이동과 초기 기울기 |
| `_criticalPopMultiplier` | 1.35 | 치명타 크기 배율 |

크기 곡선의 시간은 전체 수명에 대한 비율이다. 런타임 풀을 초기화하기 전에 설정한다. 현재 Binder는 풀을 코드로 생성하므로 코드 기본값이 소비된다. 기존 풀 초기화 뒤 시간/곡선 설정을 바꾸는 실시간 튜닝 API는 추가하지 않았다.

64개 슬롯 상한, 재사용 시퀀스, 카메라 손실/재바인딩·비활성화·파괴 정리를 유지한다. 각 슬롯은 이동·크기/기울기·알파의 트위너 3개를 초기화 때 준비하고 Show마다 새 트윈이나 문자열을 만들지 않는다. UI 시간은 기존대로 `SetUpdate(true)`를 사용한다. 넘치는 숫자는 기존 정책대로 생략한다.

## 검증

2026-10-26 `DamageNumberPoolPlayModeTests` 8개(등장 피크·읽기 시간·치명타 구분·좌우 분산·재사용 초기화 포함), `DamageNumberBinderPlayModeTests` 4개가 통과했다. 기존 Binder 테스트의 RPC 반사 호출에 누락되어 있던 마지막 `isDamageOverTime=false` 인자를 추가해 현재 서명과 맞췄다. 네트워크 실행 코드는 바꾸지 않았다.

`DamageNumberPoolTests` EditMode 5개도 통과했다. 최초 검토 영상은 `Show` 직접 호출로 촬영했으며, 그 시점에는 `Dev_ForestPlateauHitFeedback`의 실제 타격에 연결되지 않았다. 이후 아래 개발 씬 연결을 추가했다. 기존 Binder를 사용하는 전투 화면에도 수정된 풀의 애니메이션이 적용된다.

## 히트피드백 개발 씬 연결

`DevHitFeedbackSpawner`가 시작할 때 플레이어 `OutputCamera`에 연결된 `DevHitDamageNumbers` 풀을 만들고, 기존 플레이어 `Hit` 이벤트의 `TakeHit` 성공 후 숫자를 표시한다. 일반 타격·강공격·치명타·처치에 같은 경로를 사용하며, 죽은 대상처럼 타격이 거절되면 숫자를 추가하지 않는다. 원본 씬 저장이나 수동 Canvas 배치는 필요 없다.

이 개발 씬은 실제 HP 대신 맞은 횟수로 처치를 정하므로 표시값은 스포너 Inspector의 개발용 값이다. `_devNormalDamage=100`, `_devHeavyDamage=160`, `_devCriticalDamageMultiplier=2`가 기본값이며 기존 치명타 확률 `_devCritChance`를 따른다. 이 값은 릴리즈 밸런스나 서버 피해량을 바꾸지 않는다.

스포너 비활성화 때 숫자를 정리하고 숨기며, 재활성화하면 같은 풀을 재사용한다. 스포너 파괴/씬 종료 때 소유한 풀도 파괴한다. 카메라가 바뀐 경우 기존 풀에 다시 연결한다.

| 주장 | 수준 | 증거 등급 | 실행 수단 | 실제 결과 | 상태 |
|---|---|---:|---|---|---|
| 개발 씬 시작 시 자동 연결 | L2 | 2 | 실제 씬 Play, 풀 계측 | 초기화된 `DevHitDamageNumbers` 1개 | 완료(검증됨) |
| 실제 타격 경로의 숫자 | L2 | 2 | 플레이어 `DealDamageInCone`의 물리 조회→Hit 이벤트→스포너 경로 | 일반 `100`, 치명타 강공격 `320!`, 각각 활성 숫자 1개 | 완료(검증됨) |
| 처치와 거절된 타격 | L2 | 2 | 같은 실제 공격 판정 호출 | 처치에 숫자 1개, 이미 죽은 대상 재타격은 추가 0개 | 완료(검증됨) |
| 비활성화/재활성화 | L2 | 2 | 스포너 disable/enable | 활성 숫자 0/풀 숨김, 재활성화 후 같은 풀 1개 | 완료(검증됨) |

일반 숫자가 실제 GameView에 보이는 화면도 확인했다. 정지 캡처는 이벤트로 생성된 숫자의 크기 피크를 촬영 중에만 잠시 유지했다. 수동 사용자 입력과 실제 서버 접속 전투를 수행했다는 의미는 아니다.

로컬 표현 검증이다. 실제 다인 서버 흐름, Player 빌드, 폰트/해상도별 가독성과 성능 예산은 미검증이다. 기본 40m 카메라의 실제 GameView로 검토하며, 혈흔 건조는 [혈흔 사용 안내](HIT_FEEDBACK_BLOOD_USAGE.md)를 따른다.
