# 개발 씬 피격 혈흔

`Dev_ForestPlateauHitFeedback`에서 타격 순간 분사, 날아가는 사체의 출혈, 바닥에 남는 혈흔을 재생한다. 혈흔은 `DevHitFeedbackSpawner`와 `HitFeedbackDirector`를 사용하는 개발 씬에 연결하며 서버 피해 판정은 변경하지 않는다. 공용 사체의 래그돌 정책은 아래 절을 따른다.

## 프리팹과 적용 경로

- 프리팹: `Assets/02.Prefab/VFX/HitFeedback/Resources/DevHitBlood/PF_DevHitBlood.prefab`.
- 풀: `Assets/01.Scripts/99.Dev/Combat/HitFeedback/Blood/DevHitFeedbackBlood.cs`.
- 사체 연결: 같은 폴더의 `DevCorpseBloodTrail.cs`.
- 텍스처/재질: 같은 폴더의 `Resources/DevHitBlood/T_BloodSplatAtlas.png`, `M_BloodSpray.mat`, `M_BloodGround.mat`.

Director의 `_bloodPrefab`이 비어 있으면 `Resources/DevHitBlood/PF_DevHitBlood`를 읽는다. 따라서 위 프리팹 Inspector의 설정이 다음 게임 시작에도 적용된다. 프리팹이 없으면 경고와 함께 코드 기본값으로 생성한다. `_useBlood`는 혈흔 사용 여부이며 기존 불똥 토글과 독립적이다. 원본 씬을 저장하거나 새 컴포넌트를 수동 배치할 필요는 없다.

원점과 크기는 월드 미터다. 풀 루트는 움직이지 않는 위치에 두고 스케일 `(1, 1, 1)`을 사용한다. 공중 입자는 월드 공간에서 시뮬레이션한다. 혈흔과 방울은 표현 전용이며 Collider, 피해량, 공격 판정이나 서버 시계를 추가하지 않는다.

## 호출과 사체 추적

| API | 계약 |
|---|---|
| `Burst(point, direction, isKill, isCritical)` | 확정된 피격 접점에서 분사. `direction`은 공격 진행 방향이며 피는 접촉면 바깥쪽과 위쪽으로 튄다 |
| `FollowCorpse(anchor, freezeFrames)` | 실제 움직이는 골반 뼈를 추적하고 지연 프레임 뒤부터 방울을 낸다. 반환값은 추적 핸들 |
| `StopFollowing(handle)` | 해당 추적만 취소. 오래된 핸들이 새 추적을 취소하지 않음 |
| `StopAll()` | 공중 입자, 낙하 방울, 추적, 바닥 자국을 즉시 정리. 비활성화도 같은 동작 |

기존 `ReportHit -> OnPlayerHit -> HitFeedbackDirector.PlayHit`가 `Burst`를 호출한다. 몬스터 초기화 때 골반 뼈와 풀을 캐싱하고, 사망 때 원본 모델에 복제용 연결 컴포넌트를 잠깐 붙인다. `EnemyCorpse.Launch`가 모델을 복제하면 골반 참조도 복제된 뼈로 연결된다. 원본 연결은 제거하고 사체 복제본만 출혈한다. 뼈가 실제로 날아가거나 회전하는 위치를 사용하며 몸이 사라지거나 비활성화되면 추적을 끊는다. 모델 없는 캡슐은 기존 루트의 비행을 추적한다. 혈흔 연결은 공용 사체의 공개 API를 사용한다.

### 사체 래그돌 정책

공용 `Assets/01.Scripts/03.AI/Enemy/View/EnemyCorpse.cs`는 남아 있는 사체를 최대 16개로 제한하며, 뼈가 있는 각 사체를 기존 래그돌 또는 자동 생성 래그돌로 활성화한다. `EnemyCorpseRagdoll`은 3초가 지나거나 1초 이후 모든 뼈가 잠들면 물리를 멈춰 자세를 유지한다. 스킨 뼈가 없어 래그돌을 만들 수 없는 모델만 기존 포물선 비행을 사용한다.

2026-10-26 별도의 래그돌 8개 제한을 제거했다. 이전에는 9번째부터 애니메이션 자세로 굳은 채 날았고, 물리가 이미 멈춘 사체도 8개 집계에 남아 추가 사망에 같은 문제가 이어졌다. 사체 16개 상한과 자동 물리 종료는 유지한다. 이 정책 변경은 `EnemyCorpse`를 사용하는 개발 씬과 릴리즈 표현 모두에 적용되며 혈흔의 릴리즈 연결을 의미하지 않는다. 최악의 동시 뼈 물리 수는 증가하므로 Player 성능 예산은 별도 검증이 필요하다.

`Assets/Tests/PlayMode/EnemyCorpseRagdollTests.cs`의 5개 회귀 시험으로 기존/자동 생성 래그돌 12개, 이전 사체 물리 종료 후 추가 사망, 20개 요청 시 16개 상한, 뼈 없는 모델의 대체 비행을 확인했다. 수정 전 4실패/1통과, 수정 후 5통과였다. 실제 Beast/Vendigo 혼합 모델도 12/12 활성화, 이전 물리 종료 후 추가 4개를 포함한 16/16 활성화를 확인했다. 추가 처치의 혈흔 추적도 유지됐다. 로컬 표현 검증이며 빌드, 다인 실행과 Player 물리 성능 예산은 미검증이다.

낙하 방울은 중력으로 이동한다. 직전 위치부터 다음 위치까지 정적 지형과의 교차를 검사하고 땅에 닿은 곳에 얼룩을 남긴다. 살아 있는 캡슐/구형 충돌체, CharacterController와 Rigidbody가 있는 래그돌은 바닥으로 취급하지 않는다. 바닥 얼룩은 3x3 꼭짓점을 각각 지형에 맞추고 표면 법선 방향으로 0.02m 띄운다. 정상적으로 맞출 바닥이 없거나 꼭짓점 높이 차가 0.65m를 넘으면 해당 얼룩을 생략해 절벽을 가로지르거나 공중에 뜨는 카드를 줄인다.

## Inspector 설정

설정을 바꾼 뒤 플레이를 다시 시작한다. 재질, 파티클 모듈과 바닥 페이드 트윈은 `Awake`에서 준비한다.

| 설정 | 기본값 | 용도 |
|---|---|---|
| `_hitSprayCount`, `_killSprayCount` | 24, 42 | 타격/처치 순간 공중 분사 개수 |
| `_spraySpeed` | 3~8m/s | 분사 속도 |
| `_spraySize`, `_sprayLifetime` | 0.55~1m, 0.16~0.4초 | 분사 카드 크기와 수명 |
| `_freshColor` | 적색 | 분사와 낙하 방울 색 |
| `_hitDropCount` | 7 | 타격 시 실제로 떨어지는 방울. 처치는 두 배 |
| `_dropSize`, `_dropSeconds` | 0.25~0.42m, 2.5초 | 방울 크기와 최대 비행 수명 |
| `_dripInterval`, `_bleedSeconds` | 0.12초, 2.6초 | 사체 출혈 간격과 최대 지속 시간 |
| `_impactStainSize` | 1.2~2.2m | 타격 접점 아래 얼룩 크기. 처치/치명타는 소폭 확대 |
| `_dripStainSize` | 0.4~0.8m | 방울 착지 얼룩 크기 |
| `_stainSeconds`, `_fadeSeconds` | 45초, 5초 | 총 수명 45초. 앞 40초 유지 후 마지막 5초 페이드 |
| `_stainColor`, `_groundLayers` | 짙은 적색, 전체 | 지면 색과 바닥 쿼리 레이어 |

사체가 잠깐 움직이지 않는다고 즉시 출혈을 끊지 않는다. 최소 0.6초 진행한 뒤 낮은 속도가 0.35초 이어지면 바닥에 마지막 얼룩을 남기고 종료한다. 방출된 방울은 남은 수명 동안 떨어진다. 사체 속도의 일부를 방울에 물려 주므로 비행 방향을 따라 자국이 이어진다.

분사 풀 12칸, 낙하 방울 256개, 사체 추적 32개, 바닥 얼룩 160개로 제한한다. 넘으면 기존 칸을 재사용하며 오래된 자국은 45초보다 일찍 교체될 수 있다. 바닥 자국마다 메시 1개와 재사용 페이드 트윈 1개를 준비한다. 프레임마다 새 재질/배열/트윈을 만들지 않으며, 방울과 추적이 모두 끝나면 물리 표현 코루틴도 멈춘다.

## 텍스처와 재질

4x4 불규칙 액체 얼룩 알파 아틀라스를 내장 `imagegen`으로 신규 생성했다. 피나 신체 사진을 사용하지 않았으며 RGB 마스크에 Unity 재질/입자 색을 입힌다. 제작 원본은 로컬 생성 이미지에 보존하고, 런타임 참조 PNG는 위 Assets 경로에 복사했다. 상세 생성 프롬프트와 검토 기록은 개인 작업 기록에 보존한다.

Unity 임포트는 1024x1024 RGBA32, sRGB, 알파 투명, Clamp, Bilinear, 밉맵 사용이다. 분사는 기존 URP `Universal Render Pipeline/Particles/Unlit`, 바닥은 `Universal Render Pipeline/Lit`의 투명 재질과 Smoothness 0.45를 사용한다. 가산 발광을 사용하지 않는다. 바닥 표면 법선과 조명/반사로 젖은 얼룩을 표현하며 별도의 두께/AO/노멀맵을 베이크하지 않는다. 얇은 표면 마스크이고 가림을 만드는 독립 3D 형상이 없기 때문이다. 메시 LOD나 피해 Collider도 추가하지 않는다. Blender 연결/설치는 확인되지 않아 Blender 렌더를 사용하지 않았다.

프리워밍 대상과 런타임 카탈로그 제외 범위는 [맵 성능 준비](MAP_PERFORMANCE_PREPARATION.md#개발-씬-준비-대상---피격-혈흔)를 따른다.

## 검증 범위

2026-10-26 Unity 6000.4.7f1, URP PC/DX11, 개발 씬의 기존 피격 직접 호출로 확인했다. 거리 40m/FOV30에서 일반 타격, 사망 비행 중 출혈, 착지 뒤 바닥 자국을 실제 카메라로 녹화했다. 주변 몬스터는 표시하되 촬영 조건에 따라 추격/입력을 일시 고정했다. 씬은 저장하지 않고 테스트 설정은 플레이 종료로 복원한다.

| 주장 | 수준 | 증거 등급 | 실행 수단 | 실제 결과 | 상태 |
|---|---|---:|---|---|---|
| 피격 분사와 사체 출혈 | L2 | 2 | 기본 40m 시점 Unity 카메라 녹화, 추적 계측 | 비행 중 골반 위치가 이동하며 추적 1개 유지. 종료 뒤 0개, 바닥 혈흔 잔존 | 완료(검증됨) |
| 방울의 실제 착지 | L2 | 2 | 정적 바닥과 캐릭터 캡슐을 겹친 시험 | 방울 7개가 모두 착지. 초기 1개 포함 얼룩 8개, 방울 0개 | 완료(검증됨) |
| 경사면 밀착 | L2 | 2 | 평면/15도 경사면 꼭짓점과 표면 거리 조회 | 평면 0.0200m, 경사면 최대 0.020006m | 완료(검증됨) |
| 유지/페이드/정리 | L2 | 2 | 지연/트윈 진행/완료, 상한 및 비활성화 계측 | 유지 40초+페이드 5초, 중간 알파 0.25, 완료 시 숨김. 방울 256/얼룩 160 상한, 비활성화 후 모두 0 | 완료(검증됨) |
| 추적 취소와 재사용 | L2 | 2 | 새 핸들/오래된 핸들 취소와 대상 비활성화 | 오래된 취소가 새 추적을 건드리지 않음. 대상 비활성화 후 추적 0, 재활성화 후 재생 가능 | 완료(검증됨) |

재컴파일은 통과했고 새 혈흔 스크립트의 컴파일/콘솔 오류는 없었다. 별도로 기존 lilToon 설정 파일의 InitializeOnLoad/공유 읽기 오류가 관측돼 전체 프로젝트 콘솔 오류 0을 주장하지 않는다. 실제 사용자 입력 전투, 릴리즈 연결, 빌드, M2/M3, 성능/메모리 예산과 API별 셰이더/PSO 워밍업은 미검증이다. 풀 생성만으로 첫 사용 지연이 해결됐다고 해석하지 않는다.

프리팹 소비 경로를 연결한 뒤 새 플레이에서도 Resources 프리팹 로드와 실행 인스턴스의 직렬화 설정 일치를 확인했다. 누락 fallback 경고 없이 처치 시 방울 14개, 사체 추적 1개, 초기 바닥 얼룩 1개가 생성됐다. 원본 씬 저장 없이 플레이를 종료했다.
