# 실사에 가까운 3D 스타일화 판타지 에셋 제작 기본 절차

> 2026-10-01 · 공통 작업 지침. 원화의 구조와 분위기를 참고해 모델·재질·배치용 프리팹까지 제작한다.
> **별도 요청이 없어도 노멀·거칠기·AO를 포함한 재질 작업과 Unity 프리팹 구성을 진행한다.** 이 문서는 제작 기준이며 새 마을 모델의 구현 완료 보고가 아니다.

## 1. 목표와 제작 방식

[컨셉 아트](../design/concept-art.md)와 [모델 제작 목록](../design/model-production-list.md)을 먼저 읽고, 현재 Assets의 모델·재질·프리팹을 확인한다. 원화에서 보이는 형태, 사용자가 지정한 실사에 가까운 3D 스타일화 판타지 방향, 미정인 게임 규칙을 구분한다. 원화만으로 건물 용도·NPC 위치·맵 경계·캐릭터 비율을 새로 확정하지 않는다.

2026-10-01 후속 사용자 설명을 합친 자산 제작 방향은 **실사에 가까운 3D 스타일화 판타지**다. 앞선 실사 판타지 요청과 3D 스타일화 확인, 그때 생성한 시안·개별 제작 기록은 이력으로 보존한다.

2026-10-24 사용자 결정으로 최종 게임 화면은 **원신풍 툰**으로 보이게 한다. 이것은 렌더러 후처리(툰 조명 계단·경계선·색 보정)와 VFX로 하며 **모델·텍스처와 환경·캐릭터 재질·셰이더는 바꾸지 않는다.** 그래서 이 문서의 제작 기준(PBR 맵, 실제 AO, 지원 셰이더 연결)은 그대로 적용한다. 후처리·VFX 툰은 아직 구현되지 않았으므로(2026-10-24) 원화 대조와 시각 검증은 현재 화면 기준으로 하고, 구현 뒤에는 툰 후처리를 켠 화면에서도 확인한다. 화면 깊이·노멀을 쓰는 후처리라 새 불투명 커스텀 셰이더에는 DepthNormals 패스를 넣는다. 없으면 그 물체가 깊이·노멀 텍스처에서 빠져 뒤 물체 기준으로 잘못 계산된다.

원화의 큰 형태·비례·실루엣과 판타지 색감을 따르고, 석재·목재·기와·금속·천은 실제 재료의 규모와 표면 반응에 가깝게 표현한다. 석재 균열·모서리 마모·이끼 분포·목재의 결, 재료별 거칠기·노멀·PBR 디테일을 살리고 자연광에서 큰 형태와 미세 질감이 함께 읽히는지 확인한다. 디테일 밀도와 강도는 원화·카메라 거리와 대조해 조절한다. AO/PBR과 조명 분리는 그대로 적용하며 그림의 하이라이트나 그림자를 BaseColor에 복사해 검증을 대신하지 않는다. 메시 밀도와 LOD 예산은 화면 크기·실측 성능을 기준으로 따로 정한다.

| 대상 | 기본 제작 방식 | 재사용 기준 |
|---|---|---|
| 바위·유기적인 자연물·독립 조형물 | 기존 자산 확인 → 단일 물체 참조로 Meshy CLI 원본 생성 → Blender MCP 정리 | 같은 원본의 회전·크기·재질 변형으로 충분한지 먼저 확인 |
| 바닥·계단·벽·기둥·보·지붕 연결부 | Blender MCP로 치수와 접합을 맞춰 직접 제작 | 공용 규격과 피벗으로 반복 배치; 반복 경계 확인 |
| 대표 건물·광장 구성 | 공용 모듈을 조합하고 필요한 특징만 추가 | 이미 만든 건물 원본·바닥·소품을 재사용 |
| 기존 벚꽃·식생 | 기존 메시·재질·버텍스 컬러를 보존해 개선 | 새 모델 생성 전에 기존 자산과 셰이더 지원 확인 |

마을 지도 전체를 Meshy의 단일 물체 입력으로 쓰지 않는다. 모델용 참조는 한 물체가 분리된 이미지나 일관된 다각도 시트로 준비한다. 외부 소재와 생성 모델의 출처·권리 확인 상태는 [에셋 대장](../licenses/ASSET_REGISTRY.md)에 기록한다.

Meshy는 요청된 모델 제작에 필요한 원본 생성에 사용한다. 회전·재질·부분 수정은 기존 원본에서 우선 해결하고, 실패 재시도는 원인과 입력 보정 여부를 확인해 작업 ID·실제 크레딧 사용을 기록한다. 이 기본 과정이 불필요한 반복 생성이나 추가 결제까지 허용한다는 뜻은 아니다.

## 3. 재질과 AO는 기본 작업에 포함한다

### 맵과 Unity 연결

| 맵 | 제작·임포트 기준 | 기본 URP Lit 연결 |
|---|---|---|
| BaseColor | 직접광·드리운 그림자·AO를 섞지 않은 재료 색, sRGB 켬 | Base Map RGB |
| Normal | 탄젠트 공간·OpenGL(Y+) 기준, Blender 이미지 Non-Color·Unity Normal Map 임포트; 다른 규약 원본은 변환/방향 확인 | Normal Map |
| Roughness | 선형 거칠기 원본 보존; 재료별 반사 폭·마모 차이 표현 | Smoothness 변환용 원본 |
| MetallicSmoothness | 선형 데이터, 금속 여부와 `1 - Roughness`를 패킹 | Metallic = R, Smoothness = A; Metallic Alpha로 설정하고 Smoothness 슬라이더 배율은 1을 기준으로 조절 |
| AO | 실제 형상의 접촉·틈 가림을 별도 베이크, 선형 데이터 | Occlusion Map의 G 채널; 회색 AO라면 RGB에 같은 값 저장 |
| Emission·Alpha | 발광이나 얇은 면의 실루엣이 필요한 대상에 추가 | Emission Map, Base Map A·Alpha Clipping 등 해당 셰이더 지원 확인 |

URP Lit의 맵 연결·알파 클립은 [공식 Lit 문서](https://docs.unity3d.com/6000.4/Documentation/Manual/urp/lit-shader.html), 패킹 규칙은 [공식 채널 패킹 문서](https://docs.unity3d.com/6000.4/Documentation/Manual/urp/shaders-in-universalrp-channel-packed-texture.html)를 기준으로 한다. 커스텀 셰이더에 같은 입력이 있다고 가정하지 않고 실제 그래프·재질을 확인한다.

Smoothness 슬라이더는 맵의 A 값에 곱해지는 배율이다. 패킹 결과를 그대로 쓸 때는 1로 두고, 의도적으로 반사를 바꿀 때 조절한다. Normal·Roughness·AO·MetallicSmoothness 등 데이터 이미지는 Blender에서도 Non-Color로 다룬다. 노멀의 색 공간·UV와 [노멀맵 규약](https://docs.blender.org/manual/en/5.2/render/shader_nodes/displacement/normal_map.html)을 확인하고, Unity 임포트 후 요철 방향을 다시 본다.

### 반복 재질과 고유 AO의 UV 선택

기본 URP Lit은 AO를 포함한 주요 맵을 같은 UV0와 Base Map Tiling/Offset으로 읽는다. 타일링·트림시트·겹친 UV로 표면을 공유한 모델에 고유 AO만 그대로 연결하면 위치가 맞지 않는다. 다음 중 실제 형상·재질에 맞는 방법을 선택하고 기록한다.

- 고유한 베이크가 필요한 모듈은 겹치지 않는 UV0로 BaseColor·Normal·거칠기·AO를 함께 베이크한다.
- 반복되는 형상과 가림도 같은 경우에만 해당 반복 구역의 AO를 공유한다. 다른 형상의 고유 AO를 겹친 UV에 덮지 않는다.
- 타일링 표면과 고유 AO를 함께 유지해야 하면 별도 UV를 읽는 지원 셰이더 또는 지원되는 버텍스 AO를 사용한다. 기본 URP Lit에 별도 AO UV 입력이 있다고 가정하지 않는다. 기존 셰이더 변경은 실제 담당 범위와 기능 검증을 따른다.

이 동작은 설치 URP의 `Shaders/LitForwardPass.hlsl` UV 변환과 `Shaders/LitInput.hlsl`의 `SampleOcclusion(uv)`에서 확인한다. LOD에도 같은 UV 대응이 유지돼야 한다.

### AO 제작·베이크

1. 최종 사용 형상·적용 스케일·UV를 정리하고 베이크 대상 이미지와 활성 타깃을 지정한다. AO·Normal·Roughness 등 데이터 맵 대상은 Non-Color, BaseColor 대상은 sRGB로 둔다. 고밀도 원본에서 낮은 메시로 옮길 때는 투영 거리·케이지와 겹침을 확인한다.
2. AO를 별도 맵으로 계산한다. 국소 AO의 기본 예는 Cycles AO 노드의 Only Local을 켜고 AO 출력을 Emission에 연결해 Emit 유형으로 굽는 방식이다. 일반 AO 베이크 유형을 고른 것만으로 이 노드 설정이 적용됐다고 하지 않는다. 열린 표면은 흰색, 가려진 부분은 어두운 값이다. 반복 모듈은 고정될 접합과 경계를 확인하고, 이동 가능한 이웃 물체의 그림자를 자산 자체에 영구히 굽지 않는다. 고정된 조립물에서 부품 사이 접합을 포함해야 할 때는 Only Local을 끄고 해당 조립물의 가림만 베이크한다. 같은 원본 메시의 UV·표면 맵을 공유하더라도 접촉 위치가 다르면 부품별 AO와 재질 슬롯을 구분하며, 조립 위치·규모·접합을 바꾼 뒤 다시 베이크·시각 검증한다.
3. 가림 거리·샘플·해상도·UV 여백을 대상 크기와 카메라 거리로 정한다. 베이크 파일이 실제 생성됐는지 확인하고 검은 번짐·투영 오류·UV 이음·줄눈 과장 여부를 가까이서 본다. 얇은 면의 자기 가림이나 알파 카드의 사각형이 그대로 구워진 그늘도 점검한다.
   사용자가 나중에 조립할 독립 키트는 각 조각 자체의 AO를 먼저 만든다. 정렬용 갤러리 이웃의 가림이나 이전 통합 맵의 접합 AO를 영구히 굽지 않는다.
4. BaseColor는 색만 베이크한다. Diffuse 베이크라면 Color만 사용하고 Direct·Indirect를 제외하거나 색만 Emit으로 옮기는 등 결과에서 조명을 분리한다. Meshy 원본 색에 이미 그림자·AO가 보이면 정리한 뒤 별도 AO를 적용한다.
5. Blender와 Unity의 지원 셰이더에 실제 연결해 AO 켬/끔을 같은 조명에서 비교한다. URP Lit 재질 AO는 간접광에 적용되므로 그늘진 면·간접광 위주 위치에서도 확인한다. 직사광에서 차이가 작다는 이유만으로 강도를 과하게 올리지 않는다. 줄눈을 검은 테두리처럼 만들거나 BaseColor에 AO를 다시 곱해 같은 그늘을 중복 적용하지 않는다.

노멀은 표면 방향의 요철, AO는 가려진 부분의 간접광 감쇠를 표현하므로 서로 대체하지 않는다. 타깃 이미지·UV·투영·여백은 [Blender 공식 베이크 문서](https://docs.blender.org/manual/en/4.5/render/cycles/baking.html), 국소 가림 거리·Only Local은 [공식 AO 노드 문서](https://docs.blender.org/manual/en/4.5/render/shader_nodes/input/ao.html)를 참고한다. 도구 버전별 UI 명칭보다 실제 기능과 출력 결과를 확인한다.

AO 거리·샘플·연결 강도는 모델 크기·접합 깊이·카메라 거리와 실제 베이크 결과에 맞춰 정한다. 한 모델의 제작 값을 다른 모델의 고정값으로 쓰지 않는다. 텍스처 해상도도 반복 수·화면 크기·메모리·타깃 성능을 보고 선택하며 전체 마을의 예산은 아직 검증하지 않았다.

### 식생과 효과 예외

- 기존 [Vertex Color Foliage 셰이더](VERTEX_COLOR_FOLIAGE_SHADER.md)는 버텍스 컬러를 BaseColor에 반영해 구운 그늘을 보존한다. 현재 그래프에는 Normal Map·AO 텍스처·MetallicSmoothness 입력 연결이 없다. 버텍스 AO·UV·알파·조정된 노멀을 FBX와 LOD에서 보존하고 실제 지원 범위 안에서 사용한다. 같은 AO를 색에 다시 곱하지 않는다.
- 잎·꽃·얇은 천은 필요한 알파 경계, 밉맵의 실루엣 유지, 뒷면 표시·노멀·그림자를 함께 확인한다. 알파 카드에는 클립·양면 표현을 검토하고, 구멍 없는 천은 불투명 메시를 기준으로 실제 두께·양면·별도 뒷면 중 용도에 맞게 선택한다. 잎의 알파 클립을 거칠기나 AO로 해석하지 않는다. 투명 천은 정렬과 조명까지 해당 셰이더에서 확인한다.
- 물·불꽃·구름이나 Unlit 효과 등은 목적상 AO 맵을 쓰지 않을 수 있다. 표현 방식·생략 이유·시각 검증을 제작 기록에 적고 진행한다. 별도의 승인 절차를 만들지 않는다.

화면 공간 AO(SSAO)는 자산 AO의 대체 근거가 아니다. 현재 [PC 렌더러](../../Assets/Settings/PC_Renderer.asset)에는 SSAO가 있지만 [Mobile 렌더러](../../Assets/Settings/Mobile_Renderer.asset)에는 없고, 설치 URP 17.4는 SSAO와 재질 AO의 간접광 가림을 `min`으로 결합한다. 두 값이 항상 곱해진다고 가정하지 않는다. BaseColor·버텍스 색에 이미 들어 있는 그늘을 중복하는지와 PC·Mobile 양쪽 밝기를 확인한다.

이 결합은 설치된 URP 17.4.0의 `Library/PackageCache/com.unity.render-pipelines.universal@7228970dbdbf/ShaderLibrary/AmbientOcclusion.hlsl`에서 `CreateAmbientOcclusionFactor` 구현으로 확인했다.

## 4. LOD·프리팹·파일 규칙

한 텍스처를 LOD 전체에서 공유하려면 UV0 영역·재질 슬롯·노멀/탄젠트와 버텍스 컬러가 결과에 맞아야 한다. 단순 감면 뒤에도 확인하고, 리메시·UV 재배치로 대응이 깨지면 다시 베이크하거나 LOD별 텍스처를 만든다. 실루엣·알파·그림자와 AO가 전환 때 튀는지 게임 카메라에서 확인한다.

| 종류 | 경로·파일명 |
|---|---|
| 모델 | `Assets/01.Scripts/05.Art/{Characters,Environment,Props}/{에셋}/Models/SM_{에셋}_{High,Medium,Low}.fbx` (정적 3단계 LOD 예시); 리깅 모델은 `SK_` |
| 텍스처 | 같은 에셋의 `Textures/T_{에셋}_{BaseColor,Normal,Roughness,AO,MetallicSmoothness,Emission}.png` 중 실제 사용 맵 |
| 재질 | 같은 에셋의 `Materials/M_{에셋}[_{부위}].mat` |
| 배치용 프리팹 | `Assets/02.Prefab/{Characters,Environment,Props}/{에셋}/PF_{에셋}.prefab` |

접두사·폴더 규칙은 [씬·에셋 안전](SCENE_AND_ASSET_SAFETY.md)을 따른다. High·Medium·Low는 기존 돌바닥·부유석의 LOD0·1·2 이름 사례이며 LOD 개수나 전환 비율을 모든 모델에 강제하지 않는다. 축·단위는 FBX 설정뿐 아니라 Unity 임포트 치수와 루트 스케일로 확인한다.

프리팹 루트·피벗은 배치 용도를 기준으로 정하고 LOD끼리 일치시킨다. 바닥은 이동 높이와 단순 충돌면을, 건물은 출입·가림·이동 공간을, 장식은 Collider가 필요한지 확인한다. 배경 장식의 복잡한 렌더 메시를 충돌 메시로 자동 채택하지 않는다. 에셋의 역할이 바뀌면 충돌도 다시 검증한다. 이동·이름 변경은 Unity 에디터에서 하고 `.meta` GUID를 유지한다.

플레이어를 가리는 나무·구조물은 [화면 가독성 기준](../design/experience-service.md#8-미술음향화면-기본안)의 주변 투명화를 받아야 한다. 게임 카메라가 카메라와 플레이어 사이 원뿔 안의 픽셀을 디더로 비우며, 이 값을 읽는 셰이더를 쓴 재질만 비워진다(2026-10-02).

| 대상 | 셰이더 |
|---|---|
| 건물·나무·바위·소품처럼 플레이어를 가릴 수 있는 불투명 재질 | `Shinshi/Environment/Lit Occlusion Fade` (URP Lit과 속성·인스펙터가 같다) |
| 잎·꽃 알파 카드 | `Shinshi/Environment/SG_VertexColorFoliage` (그래프에 투명화 노드 포함, 재질의 Alpha Clipping을 끄면 비워지지 않는다) |
| 지형·바닥·포장·부유섬 바닥·원경 | URP Lit 유지. 플레이어 발밑 바닥이 뚫리지 않게 한다 |
| 새 커스텀 셰이더 | `Assets/01.Scripts/05.Art/Shaders/OcclusionFade/ShinshiOcclusionFade.hlsl`을 포함해 색·깊이·노멀 패스에서 같은 픽셀을 버린다. 그림자 패스는 비우지 않는다 |

투명화 범위 값은 `CameraConfigSO`에 있고 셰이더 식은 `OcclusionFadeShape`(커서 클릭 판정)와 같아야 한다. 구운 오클루전 컬링의 고정 occluder로 쓰면 비워진 뒤의 플레이어가 컬링될 수 있으므로 [맵 성능 준비](MAP_PERFORMANCE_PREPARATION.md)의 투명화 대상 제외 규칙을 따른다.

## 5. 원화 비교와 완료 확인

형상은 같은 각도·프레이밍·미터 기준 물체로 비교하고, 재질은 고정된 노출·화이트밸런스·배경·광원 아래에서 비교한다. 중립 조명과 실제 게임 조명을 각각 확인해 색·거칠기·노멀·AO가 조명 변화에도 읽히는지 본다. 원화에 없는 강한 색조 보정이나 과한 역광으로 표면 오류를 가리지 않는다. 반복 모듈은 최소 인접 배치와 2×2 구성을, 대표 모델은 근거리와 게임 카메라 거리에서 확인한다.

세부 품질 검수와 수정은 사용자의 추가 지시 없이 기본으로 수행한다. 근거리 표면과 모든 LOD의 앞·뒤에서 과한 노멀·부자연스러운 금속성/거칠기·UV 이음·작은 구멍·중복 면·감면으로 생긴 변형을 찾아 원인을 고치고 같은 조건으로 다시 비교한다. 검수 이미지가 비어 있거나 카메라가 모델을 놓친 경우에는 실제 메시 경계를 기준으로 다시 촬영한다. 원본 노멀 보존과 의도적인 기하 노멀 재생성의 검증 근거를 구분한다.

텍스처는 Unity 임포트 해상도·플랫폼 압축·CPU 읽기 복사·밉맵 스트리밍을 함께 확인한다. 고해상도 제작 원본과 개별 베이크 맵은 Assets 밖에 보존하고, 런타임에는 실제 셰이더가 사용하는 맵만 넣는다. 지원되는 URP Lit 재질은 금속(R)·AO(G)·매끄러움(A)을 하나의 선형 맵으로 묶어 공유할 수 있다. 작은 모듈부터 임포트 해상도를 낮추고 근거리/게임 거리에서 재검수한다. 아틀라스는 출력 크기·패킹 효율·텍셀 밀도·베이크 중 임시 메모리를 비교한 뒤 적용하며, 아틀라스 개수 감소를 메모리 감소로 간주하지 않는다. 메모리 기록에서는 원본 파일 크기, 압축 형식의 예상 저장량, 실제 로드된 텍스처 측정을 구분한다.

에디터 확인은 저장하지 않는 임시 PreviewScene·PreviewRenderUtility 등으로 먼저 진행해 기존 씬을 바꾸지 않는다. 게임 카메라·조명이나 플레이 환경이 없으면 중립 프리뷰와 참조 확인을 완료하고, 실제 게임 조건의 확인은 미검증으로 남긴다. 임시 렌더로 게임 검증을 대신했다고 하지 않는다.

- [ ] 원화 ID·목표 시안·기존 자산 재사용 여부와 출처를 기록했다.
- [ ] 실제 치수·피벗·접합·UV·노멀·토폴로지·LOD를 확인했다.
- [ ] BaseColor·Normal·Roughness와 실제 AO 또는 지원되는 버텍스 AO를 제작·연결했다. 예외는 이유를 기록했다.
- [ ] 패킹·색 공간·알파·뒷면과 AO 중복 여부를 실제 셰이더에서 확인했다.
- [ ] FBX·재질·텍스처를 연결한 `02.Prefab/` 프리팹이 있고, 필요한 Collider 설정 또는 장식용 생략 이유를 확인했다.
- [ ] 에디터 프리뷰·반복 배치·LOD 참조·누락 재질·메타·GUID와 임포트 전후 신규 Console 진단을 확인했다.
- [ ] 실행한 이동·충돌·연속 LOD·전투 가독성·성능·빌드 검증과 미실행 항목을 구분했다.
- [ ] 스크린샷·베이크 결과·집계·출처 대장을 남기고 기존 씬 변경 여부를 기록했다.

**모델 제작 완료는 FBX 출력만으로 보고하지 않는다.** 재질·AO·LOD·필요한 충돌 구성을 포함한 배치용 프리팹이 있어야 한다. 검증 표현은 [검증 플레이북](../ai/03_VERIFICATION_PLAYBOOK.md)을 따른다. 에디터 임포트·프리뷰 확인은 게임플레이·성능·빌드 통과를 뜻하지 않으며, 미검증 항목과 이유를 남긴다.

## 6. 모델별 짧은 인수 노트

모델별 상세 디자인·제작·비교 기록은 Git에서 제외된 `.claude/docs/{처음 쓴 날짜}/`에 보관하고 아래 템플릿을 사용한다. 공유 [모델 제작 목록](../design/model-production-list.md)에는 배치용 프리팹 경로·사용 조건과 검증 범위만 요약하고, 출처·사용조건은 [에셋 대장](../licenses/ASSET_REGISTRY.md)에 남긴다. 공유 문서를 읽는 데 개인 상세 기록이 필요하지 않도록 한다. 개인 세션 인수인계 기록의 위치·절차는 저장소 지침을 따로 따른다.

```text
에셋 / 용도 / 상태:
참조 ID·목표 이미지 / 재사용한 자산:
원본·출처·라이선스 확인 상태 / 생성 작업 ID·실제 비용:
Blender 원본 위치 / 실제 치수·피벗·배치 간격:
LOD별 삼각형 / 공유 UV·재질·버텍스 AO 확인:
맵·해상도 / AO 제작 방식·거리·샘플·강도 / 예외 이유:
PF 경로 / 셰이더·맵 연결 / Collider·LOD 전환 기준:
확인한 프리뷰·반복 구성·메타·신규 Console 진단 / 증거 위치:
게임플레이·성능·빌드 결과 또는 미검증 이유 / 남은 작업:
```

배치용 모델은 모델 제작 목록의 해당 항목에서 `Assets/02.Prefab/` 프리팹을 찾는다. 임포트·에디터 프리뷰 확인과 게임플레이·성능·빌드 검증을 구분한다.
