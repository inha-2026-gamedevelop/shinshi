# 우편함 개발 화면

대상은 `Assets/00.Scenes/Dev_HUD/Dev_MailBox.unity`의 `MailBoxCanvas/Layout_인게임 HUD/우편함 창`이다. 릴리즈 흐름에는 연결하지 않은 UI 개발 시안이다.

## 배치와 재사용 자원

기준 해상도는 1920x1080이며 CanvasScaler의 Scale With Screen Size, Expand를 사용한다. 중앙의 1280x780 창 안에 왼쪽 우편 목록 12행과 오른쪽 상세 영역을 배치했다. 상세는 제목, 발신자와 날짜, 본문, 첨부 보상, 하단 버튼 순서다. 목록 글자는 17~19px, 상세 제목은 26px, 본문은 21px이다.

기존 `Assets/01.Scripts/05.Art/UI/GameStyle/Textures/`의 창 프레임, 제목줄, 버튼, 페이드 구분선과 빈 슬롯을 사용한다. 삭제와 뒤로 아이콘은 기존 `CharSelect/Textures/`의 은색 아이콘이며 첨부 아이콘은 `UiIconLibrary.asset`의 `item_potion_small`이다. 한글은 `Assets/01.Scripts/06.UI/Hud/Fonts/`의 동적 Korean Regular/Bold 폰트를 사용한다. 새 그래픽이나 런타임 C#을 추가하지 않았다.

원본 JSON의 ID 83개는 UiLayoutNote에 남아 있으나 배치는 후속 디자인 수정으로 바뀌었다. 목록의 중첩 Row1은 평탄화했으며 첨부 영역은 상세 아래로 옮겼다. 원본 JSON을 다시 적용하면 최종 위치와 부모 관계가 바뀌므로 재적용 전에 씬을 백업하고 대조한다. 공유되는 최종 배치의 기준은 씬이다.

## 동작과 사용 범위

- 제목, 발신자, 날짜 영역을 누르면 해당 예시 우편의 상세와 선택 표시가 바뀐다.
- 개별 체크박스와 현재 12행 전체 선택/해제를 사용할 수 있다.
- 뒤로 버튼은 상세를 닫고 우편 선택 안내를 표시한다. 목록을 선택하면 상세가 다시 열린다.
- 상단 닫기는 창 전체를 닫는다. 이후 나타나는 중앙의 우편함 열기 버튼으로 다시 연다.
- 제목줄은 기존 `UiWindowDragHandle`로 창 전체를 이동한다. 위치는 저장하지 않는다.
- 페이지는 1/1이며 페이지 이동, 삭제와 첨부 받기 버튼은 비활성화 상태다.

이 동작은 씬에 직렬화된 Button/Toggle 이벤트와 기존 드래그 컴포넌트를 사용한다. 우편 제목, 발신 정보, 본문, 소형 물약 5개는 배치용 예시이며 실제 우편 서버, 계정 재고, 읽음 상태, 삭제, 수령에 연결되지 않았다. 전역 TMP fallback이나 기존 폰트 설정은 바꾸지 않았다.

## 실제 우편함 창과 샘플 우편 (2026-10-08)

씬에는 시안 창(`Layout_인게임 HUD`, 비활성)과 별개로 `MailBoxCanvas/DevMailBoxLive`가 있다. 그 아래에 정식 `PF_MailBoxWindow` 인스턴스와 `MailBoxBinder`를 두었고 `DevMailBoxBootstrap` 오브젝트가 이를 켠다. 프리팹의 창은 꺼진 채 저장돼 있어 부트스트랩이 직접 연다.

- **샘플 모드**: `DevMailBoxBootstrap`의 `Use Sample Mail`을 켜면 로그인과 서버 호출 없이 가짜 우편 4건을 목록에 채운다. 줄을 누르면 상세 창(제목, 발신자, 날짜, 본문, 첨부, 받기)이 열린다. 이 모드에서는 `MailBoxBinder`를 꺼서 서버 요청이 나가지 않는다. 현재 씬은 이 모드가 켜진 채 저장돼 있다.
- **서버 모드**: `Use Sample Mail`을 끄고 `Login Id`를 채운 뒤 환경 변수 `SHINSHI_DEV_PASSWORD`를 설정한다. 개발 로그인으로 `LauncherSession`에 세션을 넣은 뒤 `InboxClient`가 `GET /v1/inbox`를 부른다. 수령까지 보려면 `Character Id`도 채운다. 이 경로는 구현됨·실행 미검증이다(백엔드를 띄우지 못했다).

샘플 모드 Play 검증(L2, 증거 등급 2): 샘플 4건 표시와 `1 / 1`, 줄 선택 이벤트 뒤 상세 영역에 제목, 발신자, 날짜, 본문이 채워지는 것을 Game 뷰 캡처로 확인했다. 실제 마우스 입력, 받기 버튼 동작, 서버 연결은 미검증이다.

Game 창 포커스 조작 중 Unity PlayerLoop 재귀 경고가 한 번 발생했다. 검증 세션을 다시 시작한 뒤 정상 화면과 Console 0을 확인했다. 다시 열기 버튼의 raycast는 활성화와 같은 호출 안에서 검사하면 그래픽 등록이 끝나지 않으므로 다음 프레임에 확인했다.

실제 마우스/키보드 입력, 다른 해상도와 화면비의 시각 결과, 서버 우편 연결, 삭제/수령, Player 빌드는 미검증이다. 개인 디자인 기록과 렌더는 Git에서 제외된 `.claude/docs/`에 보관한다.
